# MasterHouse 跨设备协作上下文

> 用途：与 `Assets/Developers/taslopece/` 一并同步到其他设备，作为可独立阅读的项目上下文。
>
> 更新日期：2026-08-14。本文不依赖任何设备本地绝对路径；它记录稳定共识与当前状态，不取代完整设计／技术文档。

## 1. 项目定位与协作方式

- 暂名：`The Guesthouse of Meros`。新人培训期可玩 Demo；温情叙事 RPG + 生活模拟经营，淡水彩绘本、低饱和、动物拟人。
- 核心命题是「活人感」：主角因视觉／人面识别障碍把旅客看作动物，在经营与理解具体的人中完成自我和解。不得把障碍或结局反转当作噱头。
- 决策顺序：设计目的与玩家体验 → 核心规则和内容节奏 → Demo 范围 → 技术实现与成本。主动指出体验、规则、成本和范围风险。
- 有限周期内优先交付少量完整闭环；探索想法不等于定案，确认后才写入稳定结论。

## 2. 当前核心玩法

当前闭环是：访客到访 → 接待并分配客房 → 通过房间环境条件或小游戏回应需求 → 获得满意度、经济反馈和叙事推进。

- 原「节点生产管线 → 物品仓库 → 物品交付」链路已退役：`ItemDef`、配方、`PlayerCargo` 等旧数据只作为删除过渡残留，不能为其设计新玩法。
- 需求只有两类：**条件类**（访客所在客房须有指定家具之一）与**小游戏类**（小游戏得分换算满意度）。每位访客仅一条需求，由日程直接配置。
- 家具摆在场上即生效：服务房间条件与房间装饰分。家具不再是节点关卡的产出或修复结果。
- 第一款小游戏是「修理电路」：玩家用有限导线格数和中转件，把有限电量精确分配给电池；按点亮电池比例得到 0–100 分。可无限重开，放弃不结算。

## 3. 访客、房间与四宫格 Hub

- Hub 是 2×2 连续四房间世界：起居室（0）是大堂／入口，不可分配；卧室、厨房、书房（1–3）为客房，一房一客。
- 访客状态主线：前台等待 → 接待后待分房 → 分到空客房后服务中并揭示需求 → 满足后闲逛／离场。服务中锁房；闲逛可换空房。
- 前台最多等 2 人，三间客房住满时不再投放；当天未投放的日程条目作废并警告，不顺延。
- 玩家可缩放、平移四宫格，并拖动访客分房／换房。表现层先跟手，松手后由 `VisitorManager` 业务裁决；失败必须弹回并给原因提示。
- 所有业务访客离场都留下基础金钱，避免死循环；拒绝和超时的声望惩罚暂按现有默认配置保留。

## 4. 对话与小游戏约束

- 对话系统自研：对话组由单句、事件与条件分支构成；按种族、触发类型和满意度分类。事件／条件采用 `[SerializeReference]` 多态配置。
- 对话只执行一次性状态转换或结算；离场等必发后续只能由访客状态机推进，不能依赖播完，避免 ESC 中断造成卡死。
- 模态对话和小游戏期间均以原因集合关闭营业闸门；场景气泡不关闭闸门。关闭一个原因不得误解除打烊等其他冻结原因。
- 小游戏对 Visitor／Dialogue／Economy／HouseClock 零耦合：宿主 `MinigameOverlay` 是唯一跨模块桥梁。小游戏只接收关卡并通过完成分数或放弃回调返回。
- 同一访客、同一小游戏需求反复进入必须抽到同一关卡，使用派生种子；小游戏自身允许使用 `deltaTime` 与非确定性随机。

## 5. 修理电路规则

- 一个 Pin 最多接一条线；链接不限制载量。电源的每个输出 Pin 用 `MaxRate` 提供电量。
- 中转件以 PinGroup 分组：每个输出口的电量 = `floor(组内输入总和 / 组内输出口总数)`。未接输出口的份额与除法余数都浪费。
- 电池收到量等于所有输入相加；等于需求即点亮，少于不亮，多于是否点亮由 `AllowExcess` 决定。
- 图成环在建线时拒绝；中转件移动／删除时附着导线直接删除并返还预算。没有失败和倒计时。

## 6. 架构硬约束

- 采用 MVVM：Def／SO 是运行时只读 Model；Data 是运行时状态；只有 Manager 改 Data；View 只读表现；Controller 只翻译输入。
- 常规业务逻辑采用固定确定性 tick：禁止 `Time.deltaTime`、`DateTime.Now`、无种子随机；遍历使用稳定 ID／坐标，不能依赖集合枚举顺序。
- 小游戏属于自治的 View 豁免区，只有关卡抽取必须确定性；它不跟全局 tick 绑定。
- Prefab 是布局唯一真相源：缺失报错，不回退代码布局；动态列表使用模板 Prefab 实例化。
- 内容、数值、台词和配置均以强类型 Def／SO 或 Excel 导表资产维护；禁止管道分隔字符串与重复真源。
- 存档目标为统一 JSON（`persistentDataPath`），禁止 PlayerPrefs；当前存档尚未重新接入，设置独立保存。

## 7. 当前工程状态

- 局外重构已收官，模块包括 `Core`、`HouseClock`、`Economy`、`Visitor`、`Codex`、`Dialogue`、`HouseUI`、`Furniture`、`Minigame`。
- 四宫格 Hub、访客拖拽／分房、条件类需求、家具族与装饰分循环、对话 CSV 导入链、音效系统均已落地。
- 修理电路的逻辑与 UGUI 已落地；测试场景和示例关卡已创建。后续以编辑器实跑验收为准。
- Excel 是家具、房间、访客日程与对话等表的唯一数据源：表格 → CSV → Unity 自动整表重建 SO。不要在 Inspector 手改导表资产。
- 音效统一从 `SfxManager.Play(ESfx.Xxx)` 播放；换音、音量与节流改 `SfxTable`，不得散落 AudioSource／剪辑引用。
