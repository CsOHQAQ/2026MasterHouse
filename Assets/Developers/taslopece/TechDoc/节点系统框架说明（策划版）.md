# 节点系统框架说明（策划版）

> 文档定位：面向策划的节点系统实现说明，用于内容配置、机制规划、关卡设计与需求评审。
>
> 当前版本：2026-08-13，按当前工程代码与配置资产整理。
>
> 状态说明：本文描述“现在的工程实际能做什么”。设计目标以正式设计文档为准；实现与设计不一致处会单独标注，不用当前原型反推最终玩法。

---

## 1. 一句话理解当前节点系统

当前节点系统是一套运行在有限网格画布上的轻量自动化生产框架：

`物资 → 配方 → 节点 → Pin → 连线 → 关卡 → 玩家全局货仓`

玩家在关卡画布中摆放不同功能的节点，通过节点边缘的 Pin 建立运输线，使物资按固定 tick 自动生产、加工、转运并最终进入全局货仓。

系统当前的主要决策维度是：

- 画布空间是否够用；
- 节点形状和 Pin 方向是否便于布线；
- 上下游产能是否匹配；
- 暂存容量是否造成背压；
- 分叉后的多条线如何竞争上游产物；
- 有限的可建节点数量如何分配。

当前实现适合支撑 Demo 期的基础生产链、空间布局和供需测试；尚不适合直接承载复杂升级树、多配方切换、动态技能效果或完整任务结算。

---

## 2. 系统在整体玩法中的位置

项目当前核心循环是：

1. 接待访客并理解需求；
2. 在节点画布中搭建生产管线；
3. 生产家具、装饰或服务所需物资；
4. 在 House 中消费这些产出；
5. 获得反馈并解锁后续内容。

节点系统负责中间的“生产与规划”部分。它不应成为孤立的效率小游戏，而应持续回答三个体验问题：

- 玩家为什么要生产这种物资？
- 玩家为什么要改变当前管线布局？
- 生产结果如何反馈到访客、空间布置和叙事推进？

因此，后续新增节点机制时，优先判断它是否带来了新的规划选择，而不是只增加一种数值更高的节点。

## 3. 策划需要掌握的核心对象

### 3.1 物资 Item

物资是生产、运输、配方和局外消费共同使用的基础单位。

当前可配置内容：

| 字段 | 当前用途 |
|---|---|
| 显示名 | 节点头顶信息、调试面板等位置显示 |
| 显示颜色 | 原型期用于 Pin、连线和运输脉冲着色 |
| 标签 | 供访客需求匹配使用；只需配置最具体的叶子标签 |

当前物资没有独立的重量、体积、品质、堆叠上限、价值或保质期概念。若后续机制依赖这些维度，需要新增数据与对应运行规则。

资产位置：`Assets/GameData/Items/`

### 3.2 配方 Recipe

配方描述加工节点“一批生产”时消耗和产出的物资。

当前可配置内容：

| 字段 | 当前语义 |
|---|---|
| Inputs | 开始一批加工时一次性消耗的全部输入 |
| Outputs | 一批完成后一次性写入输出暂存的全部产出 |
| WorkTicks | 一批加工所需 tick 数 |

当前规则：

- 输入齐全后才会开工；
- 开工瞬间消耗整批输入；
- 加工完成时，所有产出必须能完整放入输出暂存，否则停在“加工完成、等待出库”的状态；
- 等待出库期间不会开启下一批；
- 同一物资不要在同一个输入列表或输出列表中重复配置；
- 同一物资可以同时出现在输入和输出中，可表达催化剂式配方，但当前仍会先消耗再重新产出。

资产位置：`Assets/GameData/Recipes/`

### 3.3 节点 Node

节点是玩家在画布上摆放的功能实体。一个节点由以下公共部分组成：

- 显示名；
- 占格形状；
- 一组 Pin；
- 节点类型对应的专属参数。

节点形状由若干独立格组成，不要求是矩形。当前所有碰撞与占用判断都按实际格子逐格计算，因此可以制作 L 形、十字形或中空形状。

资产位置：`Assets/GameData/Nodes/`

### 3.4 Pin

Pin 是节点与连线的连接口。每个 Pin 同时包含“功能定义”和“空间布置”。

| 字段 | 当前语义 |
|---|---|
| 物资种类 | 该接口允许运输的物资；中转 Pin 可以留空并在运行时同步 |
| 最大速率 | 每条链接每次向该 Pin 请求的数量上限 |
| 方向 | 输入、输出，或仅中转节点使用的运行时同步 |
| 所在格 | Pin 位于节点形状中的哪个本地格 |
| 朝向 | Pin 从所在格的上、右、下、左哪一侧伸出 |
| 配对 Pin | 仅中转节点使用，指向同节点内的另一接口 |

需要特别注意：

> `Pin 最大速率`当前不是“这个接口每 tick 最多通过多少物资”的总上限，而是“每条链接单次请求最多拿多少”的上限。

例如一个最大速率为 2 的输出 Pin 同时连接 3 条线，在供货充足且三条线都到达取货节拍时，理论上三条线可以分别请求 2，总请求量达到 6。它们仍会按优先级和轮询顺序竞争节点暂存，但 Pin 本身没有统一的 2 点总流量池。

如果后续想把 Pin 设计成真正的接口总带宽，需要修改仲裁和计量方式，不能只调整当前字段数值。

### 3.5 连线 Link

连线连接一个输出 Pin 和一个输入 Pin，一条线只运输一种物资。

当前每条连线记录：

- 稳定 LinkId；
- 起点和终点 Pin；
- 运输物资；
- 优先级；
- 逐格记录的折线路径；
- 持货槽中的物资和数量；
- 取货节拍与计时；
- 在途时长与计时；
- 当前状态。

连线不是纯视觉线条：它会占据途经的每一个画布格，因此会与节点和其他连线争夺空间。

### 3.6 关卡 Level

LevelDef 是一个小关的唯一静态定义入口。

当前包含：

| 内容 | 当前作用 |
|---|---|
| Canvas | 可放置节点和连线的有效画布形状 |
| WorldOrigin | 该小关在全局网格中的原点，为多小关同场景预留 |
| PresetNodes | 进入关卡时自动生成的预置节点 |
| BuildableNodes | 玩家可建节点及其数量上限 |
| Goals | 仅占位，尚无实际字段和结算 |
| UnlockRequirement | 仅占位，尚无实际字段和解锁逻辑 |

预置节点可以分别配置是否允许移动、是否允许删除。

需要特别注意：

> `BuildableNodes` 的数量统计包含同 NodeDef 的预置节点。

例如某节点上限为 2，关卡已经预置了 1 个同类型节点，则玩家只能再建 1 个。

## 4. 五类节点的当前实现

### 4.1 资源型节点

用途：无输入，周期性产生一种物资。

可配置参数：

- 产出物资；
- 每隔多少 tick 生产一次；
- 每次产量；
- 输出暂存上限；
- 节点形状与输出 Pin。

运行规则：

1. 输出暂存未满时推进生产计时；
2. 到达生产间隔后尝试产出；
3. 如果剩余空间小于单次产量，只产出能放下的部分；
4. 输出暂存已满时，生产计时完全停止。

这意味着下游堵塞会逐步传回资源节点，并最终导致停产。

### 4.2 加工型节点

用途：消耗配方输入，经过加工时间后产生配方输出。

可配置参数：

- 当前唯一配方；
- 每种输入物资的暂存上限；
- 每种输出物资的暂存上限；
- 节点形状；
- Pin 的空间位置与朝向。

当前 Pin 数量、物资种类和方向由配方决定：输入条目对应输入 Pin，产出条目对应输出 Pin。更换配方后，编辑器会同步 Pin；相同物资和方向的旧 Pin 尽量保留原摆位。

当前限制：一个加工节点只能绑定一条配方，玩家不能在运行时切换配方。多配方选择及半成品处理属于待定 #3。

### 4.3 仓库型节点

用途：作为当前小关的产出结算出口。

当前语义不是“有容量的容器”，而是“漏斗”：

- 收到物资后立即计入全局 PlayerCargo；
- 节点内部不保留库存；
- 没有容量上限；
- 当前没有输出能力；
- 可以配置接收白名单；白名单为空表示接受任意物资。

仓库白名单只在建立连线时校验。运行中修改资产不属于正常玩家流程，当前没有对既有连线做动态重检。

### 4.4 中转型节点

用途：在有限空间中转向、转运和分流。

中转节点的 Pin 成对配置。连接一端后，系统会把物资类型与方向同步给它和配对 Pin，使另一端成为对应的输出或输入。

当前已支持：

- 单个中转节点内的单跳配对同步；
- 中转 Pin 留空后，根据连接对象自动确定物资和方向；
- 连接拆除且整对 Pin 都无连接后，恢复未同步状态；
- 中转节点拥有按物资计算的内部暂存容量。

当前未定案或受限：

- 两端同时接入上游时如何处理；
- 多个中转节点串联或成环时如何传播类型；
- 两个都未同步的中转 Pin 不能直接连线；
- 当前只做单跳同步，复杂冲突按“后连接失败”处理。

另一个重要实现语义是：

> 中转节点当前只有一个“节点级共享输出暂存”，并不是每对 Pin 各自拥有独立通道。

不同物资会按物资类型分别存放；但若同一个中转节点上有多对 Pin 同时处理相同物资，它们会从同一个共享池取货，可能形成跨配对混流。后续若需要严格的“从 A 对进入只能从 A 对出去”，需要把暂存拆到配对或通道维度。

### 4.5 条件型节点

用途：检查最近一段 tick 窗口内的持续供给是否达到要求，作为家具关卡是否修好的判据。

- 可配置多条 `(物资、需求量、窗口 tick)`，全部满足时节点才达标；
- 同一物资可以由多个输入 Pin 并联供给，到货量合并统计；
- 收到物资后立即消耗，不设暂存，也不会对上游产生背压；
- 只能由策划预置，不能进入玩家可建列表，也不能被玩家删除；
- 停止供给足够久后会重新掉回不达标，关卡随之失效。

## 5. 固定 tick 与生产流水线

### 5.1 基本时间单位

所有生产、加工、取货和运输时长都使用 tick，不直接使用现实秒数。

当前默认目标为每秒 10 tick，但该值仍属于待定 #5，可通过 GameConfig 调整。

### 5.2 每个 tick 的固定顺序

每个已加载关卡严格按以下顺序推进：

1. **投递阶段**：已经到达终点的连线尝试把货交给目标节点；
2. **节点阶段**：资源节点生产，加工节点消耗与加工；
3. **取货阶段**：空闲连线从源节点取货并进入运输。

这个顺序带来的体验结果：

- 本 tick 送到加工节点的输入，当 tick 就可以开工；
- 本 tick 新生产的产物，当 tick 就可以被连线取走；
- 逻辑结果具有稳定顺序，便于存档与复现。

### 5.3 打烊闸门

局内外共用全局 tick。正式联通后，当 House 进入当日打烊状态，节点系统停止推进 tick，以防玩家不结束当天并无限挂机生产。

当前局内独立测试场景中时钟不运行，因此不会进入打烊状态，产线可以持续测试。

## 6. 运输、背压与竞争

### 6.1 建立连线时的检查顺序

玩家从一个 Pin 拉到另一个 Pin 时，系统会依次检查：

1. 两个 Pin 是否有效且不属于同一节点；
2. 是否能解析为一端输出、一端输入；
3. 两端物资类型是否兼容；
4. 仓库白名单是否允许该物资；
5. 中转配对 Pin 是否存在类型冲突；
6. 玩家描出的路径是否连续、位于画布内，且不穿过节点、其他连线或自身。

任意一步失败都不会创建连线，并在测试界面显示失败原因。

### 6.2 手动描格布线

当前玩家从 Pin 按下后逐格描画路径：

- 只走上、右、下、左；
- 必须位于关卡画布内；
- 不能经过任何节点占格；
- 不能经过其他连线占格；
- 起点和终点位于 Pin 朝向外侧的相邻格。

拖动经过已经画过的格子时会截断回该格；单帧跨过多格时系统补全曼哈顿路径，遇到非法格只停止延伸，不会废掉前半段。松手时没有接到合法 Pin，整次绘制取消。

当前没有运行时自动改道。节点移动使端点变化后，相关连线立即进入断线状态。调试面板仍提供“删除旧线并重新执行 A*”按钮，但只作为测试便利；创建完成后直接拖排既有折线尚未实现。

### 6.3 持货槽与背压

每条连线同时最多持有一种物资和一份数量。

运输流程：

1. 空闲线到达取货节拍；
2. 按源 Pin 最大速率请求物资；
3. 取到货后进入在途状态；
4. 到达终点后，目标能收多少就交多少；
5. 交不完的余量继续留在线上；
6. 只要线上还有货，就不会回源头取新货；
7. 目标腾出空间后，连线每 tick 自动重试投递。

因此背压会自然发生：

`下游暂存满 → 连线持货阻塞 → 上游无法继续出货 → 上游暂存涨满 → 上游停产`

### 6.4 多条线竞争同一个 Pin

竞争顺序为：

1. 优先级数值更高的链接先处理；
2. 同优先级内按轮询顺序服务；
3. 轮询位置按稳定 LinkId 记录。

当前链接优先级字段已经存在，但没有玩家或策划设置入口，所有新建连线默认优先级为 0。因此现阶段实际体验主要是同级轮询。

### 6.5 连线节拍和运输时间

新建连线从 GameConfig 读取：

- 默认取货节拍；
- 默认在途时长；
- 是否按线长计算在途时长；
- 每格对应多少在途 tick。

按线长计算目前是实验开关。若启用，长线会带来实际时间成本，使理线同时具备空间优化和运输效率优化价值。

这些数值在连线创建时写入，运行时不会因修改 GameConfig 自动更新；需要重建或重载连线才能生效。

## 7. 连线状态与玩家可见反馈

| 状态 | 发生条件 | 当前逻辑 | 当前原型表现 |
|---|---|---|---|
| 空闲 Idle | 持货槽为空 | 等待取货节拍 | 物资色 |
| 在途 InTransit | 已取货、运输未完成 | 推进在途计时 | 物资色，脉冲沿线移动 |
| 阻塞 Blocked | 到终点但目标收不下 | 持货并每 tick 重试 | 灰线，脉冲停在目标门口 |
| 断线 Broken | 节点移动导致旧路径失效 | 完全停止，保留槽中货物 | 红线 |
| 类型失效 TypeInvalid | 两端类型在运行中变得不兼容 | 清空槽并停止 | 红线；复杂传播尚无正式触发流程 |

节点本身也有非法临时态：移动到越界或冲突位置时，该节点变红并停止模拟，其他合法对象继续运行。

存在非法节点或断线链接时，按架构约定应禁止存档；但统一存档系统目前尚未实现，因此当前只有状态检测，没有完整存档拦截界面。

## 8. 空间与建造规则

### 8.1 占格

- 画布决定哪些格可用；
- 节点按自身实际形状占格；
- 连线按完整路径逐格占格；
- 节点不能与节点或连线重叠；
- 连线不能与节点或其他连线重叠；
- 不支持两条线直接交叉共格；需要通过中转节点处理。

### 8.2 建造

当前 v1 规则是：

- 建造不消耗物资；
- 关卡通过 BuildableNodes 控制可建种类和数量上限；
- 不在可建列表中的节点不能建造；
- 自由调试模式可以绕过可建列表、数量上限及预置节点移动/删除限制；
- 即使在自由模式中，越界和占格冲突仍然不允许。

建造成本经济属于待定 #12。

### 8.3 移动与删除

- 玩家自建节点默认可移动、可删除；
- 预置节点按关卡配置决定权限；
- 拖动节点实时吸附到格子；
- 移动节点会立刻使所有附着连线断线，不会自动修复；
- 移动到非法位置时，节点进入非法临时态；
- 删除节点时，会同时删除所有附着连线。

当前代码中，主动删除一条正在持货的连线会使线上物资消失；调试面板“重新布线”也是先删除后重建，因此同样可能丢失断线中的持货。

这与旧架构文档中“除类型不兼容外全游戏无隐性舍弃”的强表述存在冲突，后续需要策划明确：

- 删除连线是否允许损失在途物资；
- 是否退回源节点或全局货仓；
- 是否在删除前给出明确警告。

在定案前，应把“删线丢货”视为当前原型行为，而不是最终体验规则。

## 9. 当前编辑器与内容生产流程

### 9.1 四个编辑器

Unity 菜单 `MasterHouse` 下当前提供：

| 编辑器 | 主要用途 | 新建资产位置 |
|---|---|---|
| 物资编辑器 | 配置物资名、颜色、标签 | `Assets/GameData/Items/` |
| 配方编辑器 | 配置输入、产出和加工 tick | `Assets/GameData/Recipes/` |
| 节点编辑器 | 配置五类节点、形状和 Pin | `Assets/GameData/Nodes/` |
| 关卡编辑器 | 配置画布、预置节点和可建列表 | `Assets/GameData/Levels/` |

节点编辑器当前支持：

- 新建节点资产按 `A_B_C` 规范命名：A 固定映射为输入 `Input`、处理 `Pro`、链接 `Con`、输出 `Out`；新版条件节点暂用 `Cond`，B 为形状外接范围的 `宽x高`，C 为策划手填识别符；
- 新节点创建时 B 为 `0x0`，完成形状绘制／擦除、撤销或保存后自动随外接宽高同步文件名；该规则只管理由新版入口创建的节点，不强制改名旧节点；
- 网格绘制或擦除非规则节点形状；
- 滚轮缩放和中键拖动画布；
- Pin 列表与画布双向选择；
- 直接在画布上摆放或拖动 Pin；
- 合法与非法位置预览；
- Esc 取消 Pin 摆放；
- 保存时把形状归一化到最左下 `(0,0)`。

关卡编辑器当前支持：

- 新建关卡资产按 `A_B_C` 规范命名：A 为项目级可配置下拉项，B 为 1～4 难度档，C 为策划手填识别标识；
- A 段选项在 `Project Settings > MasterHouse > 关卡命名` 中维护，只影响新建 SO 的文件名；
- 默认最小视野 `25 × 15`；
- 逐格和矩形绘制画布；
- 一键生成矩形；
- 预置节点列表与画布摆放；
- 滚轮缩放和中键拖动画布；
- 越界与重叠校验；
- 保存时把画布归一化到最左下 `(0,0)`。

### 9.2 推荐配置顺序

建议策划按以下顺序生产内容：

1. 新建物资，确定显示名、原型色和标签；
2. 新建配方，配置输入、产出和加工时间；
3. 新建节点，选择类型并配置形状、Pin、暂存与生产参数；
4. 对加工节点绑定配方并同步 Pin；
5. 新建关卡，绘制画布；
6. 投放预置节点；
7. 配置玩家可建节点及数量上限；
8. 进入测试场景，检查产线、背压、空间和产能；
9. 用暂停、单步 tick 和倍速定位数值问题。

### 9.3 当前目录问题

关卡资产目前存在单数和复数两个目录：

- 旧资产：`Assets/GameData/Level/`
- 关卡编辑器新建资产：`Assets/GameData/Levels/`

DebugPanel 已同时扫描 `Assets/GameData/Level/` 与 `Assets/GameData/Levels/`，两个目录中的 `LevelDef` 都会出现在调试面板关卡列表中。

目录统一仍可作为后续整理项；在此之前不需要批量移动已有资产，避免影响引用和其他成员的工作区。

## 10. 当前运行时测试能力

调试面板目前提供：

- 扫描并加载关卡；
- 热重载当前关卡；
- 自动将相机对准画布；
- 暂停；
- 单步推进一个 tick；
- `0.5x / 1x / 2x / 4x / 8x` 倍速；
- 按关卡可建列表生成节点；
- 自由模式下生成工程内任意节点；
- 查看 PlayerCargo；
- 查看选中节点的输入、输出、进度和 Pin；
- 查看选中连线的状态、持货、节拍、在途时间和路径长度；
- 对断线执行“删除并重新 A* 布线”。

运行时世界交互目前包括：

- 滚轮以鼠标为锚点缩放相机；
- 右键或中键拖动相机；
- 左键拖动节点；
- 从一个 Pin 开始左键逐格描画到另一个 Pin 建线；
- 左键点击节点或连线进行选择；
- 右键短击连线快速删除；
- Delete 删除选中节点或连线；
- Esc 取消选择或退出放置。

当前关卡数据会常驻保存，Controller 只操作 `ActiveLevel`；切换或关闭关卡时旧关卡数据不丢失，但节点模拟只推进当前打开关卡。所有已创建关卡的家具效果产出按全局 tick 独立推进。

| 接口总带宽 | 当前为每链接单次上限 | Pin 级吞吐预算和仲裁重写 |
| 玩家设置链接优先级 | 只有字段 | 设置入口和表现（待定 #16） |
| 创建后理线 | 创建时手动描格已实现 | 既有折线段拖动、合法性预览、提交/撤销 |
| 断线修复 | 只有 debug 重建 A* | 正式玩家交互与货物处理规则 |

| 未打开关卡模拟 | 节点停止、家具效果继续 | 正式局内外切换与表现联通（待定 #13/#19） |

后续规划上述机制时，应先确认目标体验，再判断是“增加一类配置”还是“改变运输与结算底层语义”。后者必须先形成独立规则说明，不能直接在现有字段上叠加特殊情况。

## 14. 后续机制规划的建议问题

每次提出新节点或新规则时，建议至少回答以下问题：

### 设计目的

- 它让玩家做出什么新选择？
- 它解决的是空间问题、供需问题、节奏问题，还是叙事需求？
- 如果去掉它，现有玩法会损失什么？

### 生产与运输

- 输入和输出是什么？是否守恒？
- 使用批次加工还是连续流？
- 堵塞时停止、缓存、丢弃还是转移？
- 多条线竞争时按什么规则？
- 该规则是否会绕过当前背压？

### 空间

- 节点占格和 Pin 布局是否真正影响方案？
- 连线是否需要额外空间规则？
- 是否会产生无法恢复的死局？

### 玩家控制

- 玩家在建造前、运行中和出问题后分别能做什么？
- 错误是否可见、可理解、可恢复？
- 是否需要暂停、预览、撤销或确认？

### 关卡与局外联动

- 该机制如何服务访客或 House 需求？
- 它是单关限定、房间限定还是永久解锁？
- 它需要新的任务目标、解锁条件或经济成本吗？

### Demo 范围

- Demo 必须验证的最小版本是什么？
- 哪些包装和扩展可以后置？
- 是否会引入新的存档、UI 或内容生产负担？
