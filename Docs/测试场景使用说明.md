# 测试场景使用说明

> 2026-08-07。适用对象：参与测试的策划、程序、以及后续接手的 AI agent。
> 配套阅读：《架构设计.md》（架构权威）、《测试场景需求记录.md》（本场景的需求依据）。
> 场景文件：`Assets/Scenes/TestScene.unity`。**仅支持编辑器内 Play，不支持打包运行**（需求决策 4）。

## 一、定位

本场景用于两件事：

1. **策划玩法验证**：读取节点/关卡配置，自由生成/移除节点、连线，观察生产链运转与产出。
2. **数据结构验证**：整条流程走真实框架（LoadLevel → tick 三阶段 → View 重建/轮询），不是 mock。

代码边界：View 层、交互层、Manager 广播事件、`CameraController.Focus` 都是**正式代码**（长期保留演进）；只有左侧调试面板（`DebugPanel`）和 `DebugOptions` 是一次性 debug 工具，未来可整体丢弃。

## 二、快速上手（跑通最小闭环）

1. 打开 `Assets/Scenes/TestScene.unity`，点 Play。初始画面只有深色背景——**没有自动加载关卡是有意的**，GameManager 的 startLevel 留空，加载由面板驱动。
2. 左侧面板「关卡」区点 **测试关卡**。相机自动对准 20×12 画布，画布上已预置：左侧「林场」（不可动）、中央「十字中转」（可移动不可删除）。
3. 「生成」区点 **木工坊**，移动鼠标看绿/红幽灵，在林场右侧空地左键落子；再放一个 **仓库**。Esc 或右键退出放置模式。
4. 从林场右侧的 Pin 小方块**左键按住拖到**木工坊左侧 Pin 上松开——自动 A* 布线成线。再从木工坊右侧 Pin 连到仓库左侧 Pin。
5. 观察：线上脉冲（棕色=木材）流动 → 木工坊头顶显示暂存与「加工 x%」→ 木板（黄褐色脉冲）送进仓库 → 面板「产出」区木板数字增长。闭环打通。

## 三、操作一览

| 操作 | 效果 |
|---|---|
| 左键点击 Pin 并拖到另一 Pin | 创建链接（自动 A* 布线）；失败时屏幕顶部显示原因 |
| 左键按住节点拖动 | 移动节点（附着链接立即断线变红；落点冲突则节点红色冻结） |
| 左键单击节点/连线 | 选中（白色高亮），面板「选中详情」显示数据 |
| 左键点空地 / Esc | 取消选中 |
| **右键短击连线** | 直接删除该链接（免选中，修线高频操作） |
| 右键/中键按住拖动 | 相机平移 |
| 滚轮 | 以鼠标为锚点缩放 |
| Delete | 删除当前选中的节点或链接（删节点会级联删附着链接） |
| 放置模式中：左键 | 落子（可连续摆放）；Esc/右键退出 |

预置约束：不可移动/不可删除的节点操作时会被拦下并提示，开「自由模式」可绕过。

## 四、调试面板功能

**关卡区**：列出 `Assets/GameData/Level/` 下全部 LevelDef（策划新建关卡零维护出现，没出现点「刷新资产列表」）。点击加载；当前关显示「▶ 点击热重载」。
**热重载语义（重要）**：重载 = 全量丢弃运行时状态（含你手摆的节点和连线），从 LevelDef 重新初始化。什么时候需要它——

- **不需要重载**：ScriptableObject 上的纯数值改动（产速、暂存上限、配方数量、WorkTicks 等），Play 模式下改 Inspector 即时生效。
- **需要重载**：结构性改动（画布形状、预置节点、Pin 布局、占格形状），以及切换 GameConfig 的「在途按线长」开关后刷新已有链接。

**时间区**：当前关名 + TickCount；暂停开关；「单步 tick」（点击自动进入暂停并推进一个 tick，适合逐 tick 观察投递→生产→取货三阶段）；0.5x~8x 倍速。

**生成区**：正常模式列本关可建列表（显示 已建/上限，达标置灰）；**自由模式**开关打开后列出项目全部节点、无视数量上限与预置约束——注意自由模式只绕过资格校验，**放置合法性（占格/越界）仍走真实规则**，不会造出脏数据。

**数据区**：PlayerCargo 累计产出（仓库是漏斗：收到即从关内消失、计入这里，这是产出验证的唯一出口）；选中节点/链接的实时详情。**选中断线（红色）链接时出现「重新布线」按钮**：删除后同 Pin 重建走 A*——这是 debug 便利，正式玩法里断线只能手工删除重连（"无自动修复"是设计原则）。

## 五、画面图例

| 视觉 | 含义 |
|---|---|
| 节点底色 绿/蓝/黄/紫 | 资源型 / 加工型 / 仓库型 / 中转型（品红=NodeType 没配，去改资产） |
| 节点整体变红 + 头顶[位置冲突] | 非法临时态：冻结不参与模拟，其余对象照常跑；存在期间禁止存档 |
| Pin 小方块颜色 | 传输物资色；灰=未确定类型（中转 Pin 连线后自动同步显色） |
| Pin 内部小点 | 白=输出，黑=输入，灰=未同步 |
| 连线颜色 | 物资色=正常（空闲/在途）；**灰=阻塞**（下游满，脉冲停在目标门口）；**红=断线或类型失效** |
| 线上脉冲 | 在途货物，颜色=槽内物资；位置按在途计时插值 |
| 放置幽灵 绿/红 | 当前落点合法 / 非法 |

## 六、种子资产与数值

| 资产 | 关键数值 |
|---|---|
| 物资：木材（棕）、木板（黄褐） | 颜色即 Pin/线/脉冲用色 |
| 配方：2 木材 → 1 木板 | 加工 20 tick |
| 林场（资源型 2×2，右输出 Pin） | 每 10 tick 产 1 木材，暂存 10，满则停产 |
| 木工坊（加工型 2×2，左入右出） | 输入/输出暂存各 10 |
| 仓库（仓库型 2×2，左输入 Pin） | 白名单空=全收；无上限（漏斗） |
| 十字中转（1×1，四向 Pin） | 上下配对、左右配对；暂存每类 1 |
| 测试关卡 | 20×12 画布；预置林场+十字中转；可建 木工坊×3、仓库×2、十字中转×2 |

全局配置 `Resources/GameConfig/游戏设置.asset`：格子世界尺寸 1；tick 频率 10/秒；链接默认节拍 10 tick、在途 10 tick。注意该资产目前只显式存了 GridSize，其余按脚本默认值生效——Inspector 里打开即可看到并修改全部字段。

## 七、建议验证的机制清单

- **背压传导**：只连 林场→木工坊 不接仓库 → 木工坊输出暂存涨满 → 输出链接灰色阻塞、脉冲停门口 → 木工坊停工 → 输入暂存满 → 上游链接阻塞 → 林场暂存满停产。全程无物资消失。
- **中转"立交"**：接十字中转任一 Pin，观察其配对 Pin 自动同步物资色与方向；断开全部连线后恢复灰色。
- **断线与修复**：拖动带线节点 → 线变红传输停 → 选中线用「重新布线」或删除重连。
- **非法临时态**：把节点拖到与其他物体重叠处松手 → 红色冻结、其余照常模拟 → 再拖回合法位置解除。
- **仲裁**：两条线接同一个输出 Pin，暂停+单步逐 tick 看轮询取货是否公平交替。
- **待定 #4 A/B（在途时长按线长）**：Play 模式下勾选 GameConfig 的 `TransitTicksByLength` → 面板热重载关卡 → 重新连线，对比长短线的运输节奏（每格 2 tick，可调 `TransitTicksPerCell`）。此开关默认关，实验完记得关回。

## 八、连线失败原因对照

顶部临时消息会显示 failReason，含义如下：

| 提示 | 原因 |
|---|---|
| 无效的 Pin / 不能连接同一节点 | 起止 Pin 不合法 |
| 两端 Pin 方向不构成一输出一输入 | 方向不匹配；也包括两个未同步中转 Pin 直连（中转链传播规则待定 #2，暂拒绝） |
| 两端 Pin 物资类型不兼容 | 强类型链接，两端已配类型必须一致 |
| 无法推导传输物资类型 | 两端都没有类型信息 |
| 仓库白名单不收该物资 | 改仓库资产的 Whitelist 或换物资 |
| 中转配对 Pin 类型冲突 | 该中转已被其他物资占用（待定 #2 占位规则） |
| 找不到合法走线 | A* 无路：途径格被节点/其他连线占满，腾空间或绕行 |

## 九、明确不包含（勿当 bug 报）

理线（手动拖排走线）、多关同时加载、打包运行、保留布局的热重载、PlayerCargo 作弊增删、Goals/结算（待定 #1）、存档（待定 #9）、稳态结算（待定 #7）、多关相机聚焦（待定 #13）。断线目前只能删除重连（或面板"重新布线"）。

## 十、常见问题排查

- **面板没有关卡列表**：确认关卡资产在 `Assets/GameData/Level/` 下；点「刷新资产列表」。
- **Play 后什么都没有**：正常，先在面板点关卡加载。
- **改了配置没生效**：分清数值改动（即时生效）与结构改动（需热重载），见第四节。
- **相机没对准画布**：检查「游戏入口」上 DebugPanel 的 cameraController 引用是否指向 Main Camera 的 CameraController。
- **新建节点/物资/配方/关卡**：用菜单里的四个编辑器窗口（物资/配方/节点形状与 Pin 摆放/关卡，见架构文档待定 #11，已实现）；新资产放入 `Assets/GameData/` 对应子目录。

## 十一、给开发者 / agent 的补充

改代码前必读《架构设计.md》，特别是 §11 确定性守则。本场景相关的硬约束：

- **View 只读**（`NodeGO/LinkGO/TransferPulseGO/GridGO/GridManager/ViewManager`）：只读数据渲染，写操作必须经 Manager。连续量每帧轮询、结构变化听 Manager 广播、Load 全量重建是真相源（§2.1）。
- **逻辑层禁止** `Time.deltaTime`/`DateTime.Now`/无种子随机；一切遍历按稳定键（NodeId/LinkId）排序。
- **资格校验分层**：可建列表/数量上限/CanMove/CanDelete 在 Controller 层（自由模式只绕过这一层）；占格合法性（CanPlaceNode）在 Manager 层，任何路径不可绕过。
- **拾取不挂 Collider**：统一走 `GridPicker`（屏幕换算 + 占用索引 + Pin 布局计算）。
- 遇到「待定 #N」注释：留占位符，不要自行拍板实现。

代码地图：`Manager/`（GameManager 驱动 tick 与时间控制、LevelManager 关卡与节点、LinkManager 链接与 A*）→ `ViewModel/`（运行时数据）→ `View/`（表现）→ `Interaction/`（GridPicker + 三个 Controller）→ `Debug/`（面板，一次性）→ `Data/`（Def 与 GameConfig）→ `Editor/`（策划编辑器窗口）。
