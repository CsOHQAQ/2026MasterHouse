# 需求交付页面落地说明

> 权威依据：`Docs/架构设计.md`（§11 确定性守则、§16.2 Prefab 硬约定、§16.4 打烊闸门）。冲突时以架构设计为准。

## 1. 一句话目标

给「服务中」的访客做一个交付页面：**左访客、中交付框、右仓库**，玩家从仓库拖一件物品到交付框，访客即时给出预览反应，玩家再决定确认交付 / 拒绝交付 / 稍后再说。

## 3. 页面结构

```
┌─访客─────┐ ┌─交付框───┐ ┌─仓库───────┐
│   立绘    │ │           │ │ 草莓蛋糕  ×3│
│（差分表情）│ │  拖到这   │ │ 木板      ×7│
│ 「嗯……」  │ │           │ │ 红茶      ×2│
└───────────┘ └───────────┘ └─────────────┘
「我想要甜的、软的食物。」
预期：满意 · ◈+18 · 声望+3
        [确认交付]  [拒绝交付 声望-M]  [稍后再说]
```

- **立绘在左**，与对话框的排布保持一致（这是硬要求，不要镜像）。
- 页面是**叠加层**（`IHouseOverlay`），不是整页路由。ESC / 遮罩点击 = 「稍后再说」。
- **Prefab 是布局唯一真相源**（§16.2）：新建 `DeliveryPageView` 字段袋 + Prefab，路径登记进 `OutGamePrefabResourcePaths`；缺失是 `LogError` 不回退代码布局。
- 仓库条目走**模板 Prefab + 运行时实例化**（§16.2 动态列表项硬约定），禁止代码逐控件搭建。

### 3.1 展示信息清单

| 展示 | 说明 |
|---|---|
| 程序化需求句 | 走 `INeedPhraseBuilder`（与对话里 `{需求}` 占位符同一个组装器），如「我想要甜的、软的食物。」 |
| 奖励预期 | 交付框有物品时显示该档的档名 + 货币 + 声望，取 `EconomyManager.RewardFor`；框空时显示「——」 |
| 仓库列表 | 只列数量 > 0 的条目，按 `GetSnapshot` 的稳定序（资产名）排列，滚动 |
| 拒绝代价 | 【拒绝交付】按钮上直接写明扣多少声望 |

**明确不显示**：需求 tag 列表与必要项标记。需求只以自然语言呈现，「哪一项更重要」靠预览反应去试——这是有意的信息设计，不要顺手加上去。

## 4. 交互流程

```
点击「服务中」的访客（访客栏卡片 / 场景演员，都走 HubPage.SelectGuest）
  → 打开交付页（关营业闸门）
  → 玩家从仓库列表拖一件物品到交付框
       ├ 交付框已有物品 → 替换，原物品回到列表（库存本就没扣，纯 UI 状态）
       └ 放入后：Preview 试算档位 → PreviewLine 抽一句 → 换立绘表情 + 页内气泡
                 同时刷新「奖励预期」
  → 三个出口：
       ├ 【确认交付】（框内有物品才可点）
       │     → 关页面 → VisitorManager.Submit(instanceId, item)
       │     → Submit 内部：扣库存 → 评分 → 经济结算 → 请求【完成服务】对话
       │     → 不对味则直接离场，其余三档转闲逛
       ├ 【拒绝交付】→ 关页面 → VisitorManager.Reject(instanceId)
       │     → 走【被拒绝】对话 → 离场
       └ 【稍后再说】/ ESC / 点遮罩 → 关页面，访客保持「服务中」，什么都不发生
```

- **拖拽不预扣库存**：库存只在 `Submit` 里扣。因此「稍后再说」无需任何回滚。
- **交付框状态不持久**：它是纯 UI 临时状态，不写进 `VisitorInstance`、不进存档。离开页面再进来，框是空的。
- **确认交付按钮在框空时禁用**。
- 打烊后本页面照常可用——玩家清场时需要它（§6）。

## 5. 需要新增/改动的业务接口

### 5.1 只读试算（新增）

```csharp
/// 试算满意度但不落地：不扣库存、不改状态、不请求对话。交付预览专用。
public EServeSatisfaction Preview(int instanceId, ItemDef item)
```

把现有私有 `Evaluate(instance, item)` 抽成可复用的纯函数，`Submit` 与 `Preview` 共用同一份实现——**两条路径的判定必须逐字一致**，否则预览显示「完美」结果交出去变「满意」，是最难查的那种 bug。

### 5.2 拒绝分两档（改动）

访谈定案：接待后反悔比在前台谢客更失礼，扣得更多。

```
EconomyConfig  += serviceFailedReputationPenalty   （服务中拒绝的声望惩罚，> refuseReputationPenalty）
EconomyManager += RefuseServingGuest()             （或给 RefuseGuestService 加状态参数）
VisitorManager.Reject 按 instance.State 选罚则
```

注意 `EconomyManager.RefuseGuestService` 现在没有声望下限保护之外的任何处理，新增那一档沿用同样的 `Mathf.Max(0, …)` 口径。

注意现有注释里写着「玩家拒绝与两段超时同口径」，这句要一并更新。

**【待确认】两段超时按哪档扣。** 默认实现：**按超时发生时所处状态取档**——等搭话超时用前台档，等交货超时用服务中档。理由是语义一致（这位访客在哪个阶段被辜负），且实现上就是同一个 `Reject` 分支逻辑，不必特判。

### 5.3 闸门（改动，与对话系统文档同源）

`HouseClockManager.SetRunning(bool)` 必须改成**原因集合**（任一原因存在即关闸）。持有者现已有四个：Hub 页面进出、打烊、模态对话框、本交付页。仍用单一布尔的话，交付页关闭时会把打烊状态误解冻。

交接细节：确认交付时先加对话的关闸原因、再移除页面的关闸原因（或在同一帧内完成），避免中间出现"闸门全开"的一瞬。

### 5.4 拖拽能力（新增）

现有 HouseUI 是纯点击交互，只有家具模式有拖拽而那是独立模式。本页面需要在 UGUI 层做一套**列表项 → 交付框**的拖拽（拖起、跟随、命中判定、落空回弹）。这套东西目前项目里没有，估工时不要按"加个按钮"算。

## 6. 与打烊清场的关系（风险提示）

打烊后玩家必须逐个处理未处理访客才能点【结束今天】（§16.4）。对「服务中」的访客只有两条路：交付，或拒绝。

因此存在一个可预见的挫败场景：**仓库空了、造不出东西了，玩家被迫拒绝，而服务中拒绝扣得更多**。这不是 bug，是 §5.2 分档带来的必然结果。是否需要缓解（例如打烊后拒绝按前台档、或给一次"歉意打发"的低惩罚选项），**留给策划在实测后决定**，本期不做。

## 7. 明确不做 / 待确认

**不做**（§16.6「只为已有内容建结构」）：

- 多件提交 / 提交篮（评分模型是单件，不要为"以后可能"留结构）
- 交付页内切换其他访客（单人聚焦；要换人先退出）
- 仓库排序、筛选、搜索、分页（稳定序 + 滚动够用）
- 交付框状态持久化
- 复用/改造 `EHousePanel.Inventory` 占位页

## 7.5 落地记录（2026-08-12，代码已完成）

本节记录**文档没覆盖、落地时补的决策**（均经访谈确认），以及实现上的取舍。文档本体的设计未变。

| 项 | 落地结论 |
|---|---|
| 物品图标 | `ItemDef` 新增 `Sprite icon` 字段。美术未接入，**当前全部为空**，条目按 `DisplayColor` 画占位色块；**缺图不报错**（明示的过渡态，不是配置事故） |
| 预览时的立绘表情 | 文档只写「换表情」，映射在 `DeliveryOverlay.EmotionBySatisfaction` 写死：不对味→失望 / 一般→困惑 / 满意→高兴 / 完美→惊讶；空框→平静 |
| `{物品名}` 占位符 | 原实现只认 `VisitorInstance.SubmittedItem`（交付**之后**才有值），预览单句里写 `{物品名}` 会渲染成「这个」。新增 `GameplayContext.PreviewItem`，格式化时优先取它——预览单句现在能正常引用框里那件东西 |
| 确认交付后的对话 | 维持 §4 原流程：**交付页立即关 → `Submit` → 全屏 GVN 对话框播【完成服务】**。页内气泡只服务于交付预览 |
| 退栈顺序 | 【确认交付】/【拒绝交付】必须**先弹栈关页、再调业务**：`Submit`/`Reject` 内部会同步压入对话层，先调业务的话 `PopOverlay` 弹掉的会是对话框。两步在同一调用栈内完成，tick 插不进来，§5.3 担心的「闸门全开一瞬」不会发生 |
| 页内气泡 | 交付页 Prefab 自带气泡节点，**不复用**场景演员的 `OutGameVisitorBubble`（那是 `internal` 的世界空间组件、自带随机符号循环）。停留时长仍取 `VisitorTuningConfig.bubbleHoldTicks`，表现层换算成秒 |
| 仓库列表滚动 | 条目消费掉拖拽事件，所以列表**不能靠拖动滚动**（滚轮与滚动条照常可用）。竖直拖动转发给 ScrollRect 要引入方向阈值与两套手势的边界情况，现阶段物资种类少，不值当 |
| 仓库列表刷新时机 | 打开时建一次即可：页面开着的时候闸门关着，局内产线不产出、库存不会变 |
| 闸门 | `EClockStopReason` 新增 `DeliveryPage`，且**计入 `IsWorldFrozen`**（验收要求「页面开启期间局内产线停 tick」）。打烊仍是时间的纯函数，交付页开合不会误解冻打烊 |
