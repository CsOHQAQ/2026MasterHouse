## 1. 一句话目标

把对话内容从「散落的 SO 资产 + Unity 编辑器窗口」搬进 **Excel 一张表**，
让配置有且只有一个家；顺带把访客状态机上几处对不上的地方一并理顺。

## 2. 八个对话分类（`EDialogueCategory`）

| key | 中文 | 触发时机 | 代码位置 |
|---|---|---|---|
| `firstMeeting` | 初次见面 | 首次点击前台**队首**访客 | `VisitorManager.RequestTalk` |
| `waitingReception` | 等待接待 | 同一位前台访客的二次点击（`MetPlayer` 已置位） | 同上 |
| `needTalk` | 需求对话 | 入住并**已开口示意**后点击他 | 同上 |
| `feedbackDisappointed` | 需求反馈·失望 | 服务超时 | `SettleNeedResult` |
| `feedbackPlain` / `feedbackFine` / `feedbackPerfect` | 需求反馈·一般/还行/完美 | 结算档位 | 同上 |
| `smallTalk` | 闲聊 | 停留期冒泡（场景气泡，不开模态） | `TickStates` |

**没有独立的「被拒绝」分类**：拒绝的台词是【初次见面】/【等待接待】组里那个「拒绝」选项的子句。
**没有独立的「验收」分类**：验收就是【需求对话】里那个挂 `RoomHasNeedFurniture` 的选项——
一次点击既听需求又能交付，比拆成两类少一半配置量，而且「进屋就发现房里正好有他要的东西」
那个瞬间的爽感是即时的（盲选房的赌注这才算真的兑现）。

## 3. 数据形态

```
Excel/对话表.xlsx（唯一源，三页：对话组 / 对话内容 / 参考）
  └ Tools/导表/export_dialogue.py → Assets/Configs/对话组表.csv + 对话内容表.csv
       └ DialogueCsvImporter（整表重建，有错就整体不落盘）
            └ Assets/Resources/OutGameUI/DialogueTable.asset
                 ├ groups  : List<DialogueGroup>      { id, steps }
                 └ entries : List<DialoguePoolEntry>  { groupId, raceId, needId, category, conditions }
```

运行时按 `(raceId, category)` 建一次查询索引；候选顺序 = Excel 行序（稳定可复现，§11.2）。

**选独立资产的三条老理由（diff 友好、多人并行、拖拽引用）在 Excel 成为唯一源之后全部失效**，
而散资产要付的代价是实打实的：删一行留一个孤儿 `.asset`、改一次 ID 多一份垃圾。整表重建把这些一次消掉。

### 3.1 步骤与子句

```
DialogueGroup
  └ steps: List<DialogueStep>          主线
       kind = Line | Action | Branch
       └ options: List<DialogueOption> （kind == Branch）
            ├ conditions: List<DialogueCall>
            └ steps: List<DialogueSubStep>   子句，只能 Line | Action
```

`DialogueSubStep` 是独立类型而不是复用 `DialogueStep`——**嵌套分支明确不做**，
类型上就堵死；顺带避开了 Unity 的「Serialization depth limit exceeded」递归警告。

选项子句播完 → **汇合到主线的下一步**。分支放在组尾时「汇合」天然等于「结束」，
所以不需要 `End` 标记（现有内容一个都用不上，§15.3 不预设抽象）。

跨组跳转（`next` / `nextGroup` / `MaxGroupJumps` / 成环检测）整套删除。

## 4. 条件与事件：函数注册表（零反射）

`Assets/Scripts/Dialogue/DialogueFuncs.cs` 里两张字典是唯一真相源：

```csharp
public static readonly Dictionary<string, DialogueConditionDef> Conditions = new() { ... };
public static readonly Dictionary<string, DialogueActionDef> Actions = new() { ... };
```

Excel 里写 `DayAtLeast(3)`，**导入期**由 `DialogueCallParser` 解析成
`DialogueCall { func, args[] }` 存进表，运行时直接查字典调委托。

- **零反射**：没有 `TypeCache` 扫描、没有 `Delegate.CreateDelegate`、没有 IL2CPP 裁剪风险
- **加一条判定 = 加一行代码**：判定逻辑本来就是代码，不违反 CLAUDE.md（那条管的是台词与数值）
- 这两张字典同时喂给导表校验、Excel 模板的下拉、资产校验器——一处维护三处生效
- **改函数名不再是高危操作**：`[SerializeReference]` 那条「改名 = 静默清空策划数据」的告警随之失效，
  数据在 Excel 里存的是名字字符串，改类名只要同步改表 + 重导一次

`ExecuteOnInterrupt`（ESC 时补执行未执行的事件）**删除**：八个事件里从没有一个用过它，
而「必须发生的后续推进由状态机自己走完」才是根本（§5.3 铁律①）。
`IsReward` **保留**，校验规则改为「必须是所在路径的最后一个事件」（主线末尾 / 某个选项子句末尾）。

## 5. 需求维度：专属优先

第一页的「需求ID」列写 `NeedDef` 资产名：

- `needTalk` 的**需求ID 列必填**——这一条是**导表期报错**（整表不落盘），漏填当场卡住
- 但「每条 `NeedDef` × 每个种族都配齐」属**覆盖度**，校验器只报**警告**不报错（理由见 §7.5 第 2 条：
  新建一个 NeedDef 就把已调好的整张表废掉，代价远大于"某位访客没话说"）
- 四档反馈**选填**：填了就是专属，抽取时**专属优先**；没有专属才回落到留空的通用组
- 其余三类**必须留空**（需求还没透露 / 已经办完）

「专属优先」而不是「混着抽」的理由：策划特地为某条需求写了台词，就该说那个，
不该有一半概率被通用句盖过去。想要变化就给同一条需求多写几组，效果一样但完全可控。

条件类与小游戏类的结构差异（`RoomHasNeedFurniture` + `CompleteNeed` vs `StartMinigame`）
因此天然不用管——每条需求的组是照着它自己那一类写的。

## 5.5 写【初次见面】/【等待接待】时必须留一个「不动手」的选项

这是最容易踩、而且**踩了完全没有报错**的一个坑：

`MetPlayer` 只在【初次见面】**正常播完**时置位（ESC 中断视为没播过）。而如果这一组的所有选项
都会让访客离开前台（接待 → 待分房、拒绝 → 离场），那就永远不存在「前台 + 已打过招呼」的实例，
**【等待接待】这一整类抽不到**——台词写了，玩家一辈子听不见。

所以【初次见面】里必须有一个「什么都不做但正常收尾」的选项（模板里那句「（先想一下）」）。
`make_dialogue_template.py` 的种子内容与 `Excel/对话表.xlsx` 的组 10001 都已经带上。

校验器**没有**拦这一条：判定它需要顺着「选项 → 子句里的事件 → 事件改哪个状态」推一遍，
是跨模块的推理，做成静态规则性价比不高。记在这里，配新的初次见面组时对着看一眼。

## 6. 访客状态机的连带改动

```
投放：日程到点 + 前台额度 2（FrontDesk + AwaitingRoom）+ HasFreeRoom
【FrontDesk】只有**队首**且 CanAcceptGuest 时可交互（有提示、点得动）
    点击 → RequestTalk → 初次见面（首次）/ 等待接待（MetPlayer 已置位）
    等搭话超时 → 直接离场，**不播对话、不扣声望**，只计一次流失
    打烊 → EndDay 自动清场（从没答应过他们什么）
【AwaitingRoom】最多 1 位（CanAcceptGuest 串行化）；无对话；**唯一阻塞【结束今天】的状态**
    刻意不给拒绝出口：接待那一刻已经保证有房，他一定分得到，所以不会死锁
【Serving ①安顿中】ScheduleNeedPrompt 排一个随机 tick；点他只有 Toast
【Serving ②已示意】头顶/卡上亮提示；**服务超时从这一刻起算**
    点击 → 需求对话（说需求 + 交付/推迟/放弃）
    交付 → CompleteNeed → 反馈档 → 转停留
    超时 → 反馈·失望 → 转停留，**不扣声望**
【Wandering】停留时长起算；闲聊冒泡；到点离场。**跨天不 roll**
所有计时按 BusinessTick：打烊停表、次日续算
```

几处关键取舍：

- **`CanAcceptGuest = HasFreeRoom && !HasAwaitingRoomVisitor`**。原来的 `HasFreeRoom` 不算待分房的人，
  会出现「3 房住满 2 间、前台 2 人，两个都接待成功、第二个再也分不到房」的死锁。
  串行化之后待分房的那位永远有房，也就永远不需要拒绝出口。
- **投放仍用 `HasFreeRoom`**（不串行化）：门口本来就允许排队，前台额度管上限；
  否则 `FrontDeskCapacity = 2` 这个常量就没意义了。
- **进屋不再自动弹对话**。自动弹会在玩家逛商店 / 摆家具时冷不丁盖上来（那两处时钟照走），
  而家具模式还禁着整个壳 Canvas——那会变成「看不见的对话框 + 关不掉的闸门」，是硬卡死。
- **`MetPlayer` 在【初次见面】正常播完时才置位**（ESC 中断视为没播过，下次仍播初次见面），
  与 recent 环的口径一致。**不进存档**（对话侧整体只留接缝，待定 #9）。
- **跨天留宿 roll 删除**：服务中/待分房都无条件跨天了，单给闲逛的掷一次骰子不一致。
  `VisitorRaceDef.stayOvernightPercent` 因此失去消费方，留着等下一轮种族表清理。

## 7.5 「点了没反应」的三道防线

对话是内容驱动的，内容缺了不该表现成「游戏坏了」。三处各管一段：

1. **导表期**——函数名、参数个数、分类、需求ID 必填、分支无条件选项，写错当场报 Excel 行号，
   且**整表不落盘**（半张表比没有表更难查）。
2. **校验器**——覆盖度问题（某需求没配 needTalk、某种族缺分类）报**警告**而不是错误：
   不该因为新建一个需求资产就把整张已调好的表废掉，而"某位访客没话说"不影响其余内容跑。
3. **运行时**——`IDialogueService.RequestVisitorDialogue` **返回 bool**，
   `HubPage.SelectGuest` 在没播出来时给一句「他现在没什么想说的 · 对话表里缺内容，详见 Console」。
   没有这条返回值，玩家点了访客、响了个交互音、然后什么都不发生，是最难排查的一类故障。

另外 `DialogueManager.AbortForMissingUi()` 兜住表现层拉框失败的两个出口
（Prefab 缺失 / 组件不对）：`TryBegin` 是**先关闸门再广播 PlaybackStarted** 的，
框没开出来就没人会调 `Close`，`ModalDialogue` 那条停走原因会把时间永久冻住。

## 8. 明确不做

- 嵌套分支（子句里再出 Branch）
- 跨组跳转（真需要时做成一条 `JumpToGroup(id)` 事件即可，是纯增量）
- 分支子句的 `End` 标记（分支在组尾时汇合 == 结束，现有内容用不上）
- 对话组权重
- 条件的 OR / NOT 组合与表达式语法（`;` 分隔的隐式 AND 是列表，不是表达式语言）
- 具名客人的专属对话（`NamedVisitorDef` 现阶段无内容）
- 对话系统的存档接入（只留接缝，待定 #9）
- 场景演员头顶的感叹号图标（**本轮只做了访客卡的角标**：世界空间标记要动 Prefab 与美术资源，
  离线改无法验证，留作下一轮）

## 9. 验收清单

- [ ] 改一句台词：改 xlsx → 双击 bat → 切回 Unity，游戏里立刻变
- [ ] 加一组新对话：只加 Excel 行，不碰代码
- [ ] 函数名写错 / 参数个数不对：导表当场报错并指出 Excel 的 sheet 与行号，**对话表不被改写**
- [ ] 新加一条需求却没配 needTalk：校验器**警告**指名是哪条需求（**不是报错**——覆盖度不阻塞导表，§7.5）
- [ ] 分支缺无条件选项：校验器报错
- [ ] 奖励事件放在路径中途：校验器警告
- [ ] 点开【初次见面】选「（先想一下）」→ 再点他，抽到的是【等待接待】而不是重放开场白
- [ ] 某个分类留空 / 条件全不满足时点访客：给一句「他现在没什么想说的」，不是静默无反应
- [ ] 前台排在后面的访客：没有提示、点了只给一句「等前面那位」
- [ ] 访客卡上的状态文案与点击后的 Toast **说的是同一个原因**（共用 `NoTalkReason`）
- [ ] 队首访客在满房时：点了给「现在腾不出房间」，不开对话
- [ ] 接待一位之后，第二位的「接待」不可用；把第一位安顿好才轮到他
- [ ] 待分房的客人拖进空房 → 先安顿一段，头顶/卡上亮提示后点他才说需求
- [ ] 条件类：房里没有那件家具时「交付」选项置灰；买/搬来任意一件后可选，选中结算完美
- [ ] 小游戏类：点他出「我来看看」，选中进入小游戏
- [ ] 服务超时：播【需求反馈·失望】、转停留、**不扣声望**
- [ ] 打烊：前台的客人自动离场；只有待分房阻塞【结束今天】
- [ ] 同一 `runSeed` 下重复进游戏，同一访客同一分类抽到同一组
- [ ] 逻辑层全文检索无 `Time.deltaTime` / `DateTime.Now` / `UnityEngine.Random`（打字机除外，它在 View 层）
