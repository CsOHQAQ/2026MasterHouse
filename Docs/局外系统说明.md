# 局外系统说明（重写版现状）

> 版本：v2.0（2026-08-10）——局外重构阶段三完成后重写。
> 定位：描述局外系统**当前长什么样、怎么跑起来**，供接手开发（人类或 agent）快速建立地图。
> 架构**决策依据**（为什么这么设计）以 `Docs/架构设计.md` §15/§16 为准，两者冲突时以架构设计为准。
> 重写前的原型代码走读见 `Docs/归档/局外原型代码走读.md`（该批代码已删除，仅存 git 历史）。

## 1. 一句话概括

局外（House 经营）已从「2869 行上帝类 + 代码兜底界面」重写为**按功能模块划分的 MVVM 结构**：内容进 Def 资产、业务逻辑挂全局固定 tick、界面一页一绑定文件且布局全部来自 Prefab。

## 3. 运行时结构

### 3.1 启动链路

```
Assets/Scenes/OutGameTest.unity（只含「局外入口」物体）
  └─ OutGameBootstrap.Start()
       ├─ 确保 GameManager 存在（缺则代码创建）
       ├─ HouseUIManager.Build()   → Canvas + EventSystem → TitlePage
       └─ 可选：HouseGmConsole（F1 面板，Inspector 勾选项）
```

与局内 `TestScene` 互不加载、互不干扰（§16.10）；局内外正式联通待定 #19。

### 3.2 tick 驱动（§16.4）

局内局外**共用同一心跳**。`GameManager.Update()` 是整个逻辑层唯一接触真实时间的位置，把流逝时间折算成固定步长：

```
GameManager.RunTick()
  ├─ LevelManager.TickAll()      局内节点模拟（打烊后停 tick，§16.4 打烊闸门）
  ├─ HouseClockManager.Tick()    时钟推进（闸门开时；到打烊时刻停走）
  └─ VisitorManager.Tick()       访客日程投放/状态机推进/超时（打烊时业务 tick 整体停表）
```

- 体验节奏「现实 1 秒 = 游戏 1 分钟」以 tick 表达：`GameConfig.HouseTicksPerGameMinute`（默认 10，待定 #18）。
- **时钟闸门是原因集合（2026-08-12）**：`HouseClockManager.SetStopReason(EClockStopReason, bool)`，任一原因存在即关闸。持有者两个——`OffHubPage`（时间只在 Hub 页面流动，家具模式不退页所以时钟照走）与 `ModalDialogue`（模态对话框期间，对话设计说明 §8）。派生出两个量，**不要混用**：
  - `IsRunning`（时钟推进 + `VisitorManager.Tick`）= 无任何停走原因且未打烊
  - `IsWorldFrozen`（门控 `LevelManager.TickAll`）= 打烊 **或** 模态对话框，**不含**页面闸门——局内测试场景没有 HubPage，跟着 `IsRunning` 走产线会永不推进
- **打烊闸门（2026-08-11）**：到达打烊时刻（`VisitorTuningConfig.closeMinute`）后一切 tick 业务冻结；玩家清完场上访客后点【结束今天】→ 日结面板 → 跳次日开门时刻。打烊是当天时间的纯函数（`IsClosedForToday`），不进原因集合。
- 所有时段划分、到访判定一律**整数比较**（分钟/tick），禁止 float 小时累加。

### 3.3 数据流

```
Def 资产（Model，运行时只读）
   ↓ GameManager 统一加载
Manager（业务逻辑，唯一修改入口）
   ↓ 事件广播（离散变化）/ 每帧轮询（连续量）
HouseUI 页面与绑定（View，只读）
```

表现层**不回写业务**：访客舞台只读 `VisitorManager` 的状态生成演员，到访与否由业务层在 tick 内判定。

## 5. 界面体系（HouseUI）

### 5.1 壳与页面

`HouseUIManager` 负责 Canvas 生命周期、**整页路由**与**叠加层栈**。ESC 语义统一为「先弹栈、再问当前页」：

```
页面（HousePage 派生，一页一文件）
  TitlePage / SavePlaceholderPage / GalleryPage / TitleSettingsPage / ExitPage / OpeningPage / HubPage

叠加层（IHouseOverlay，可退栈）
  PanelHost（9 类系统面板）/ DialogueOverlay（GVN 对话层）/ SettingsOverlay（Hub 设置）
```

**对话层的开合由业务事件驱动，不由玩家点击驱动**（2026-08-12）：`HubPage` 订阅
`DialogueManager.PlaybackStarted / PlaybackEnded` 来开关 `DialogueOverlay`。玩家点前台访客只是发起一次
`VisitorManager.RequestFirstMeeting`；接待/拒绝是【初次见面】对话末尾**分支选项上的事件**，
不再有 UI 硬编码按钮。ESC 退栈 → `DialogueManager.Interrupt()`（中断语义见对话设计说明 §5.2）。

`HubPage` 只做组装与状态协调，各区块绑定拆在六个 Binder 文件（TopBar / TaskCard / GuestRail / RightDock / RoomNav / Scene）。

### 5.2 硬约定（§16.2）

- **Prefab 是布局唯一真相源**：页面/面板只从 Prefab 实例化并绑定数据，**缺失打 Error 不回退代码布局**。同一界面禁止 Bind/Build 双实现。
- **动态列表项 = 模板 Prefab + 运行时实例化**：设备卡、档案卡、日记文章、成就行、商城卡各有模板。
- **运行时构建仅限动态表现件**：`HouseUIRuntime` 服务 Toast、开门过场、房间切换门扇、家具热点、经济数值条这类临时视觉件；它**不得**用于页面布局或列表项。（例外记录：原型期未 Prefab 化的家具 HUD 与 GM 面板亦由其服务，二轮收紧。）

### 5.3 Prefab 生成器

`HouseUI/Editor/OutGameUIPrefabGenerator`：编辑器聚焦时**只补缺失、不覆盖手调**；`Tools/MasterHouse/OutGame UI/Rebuild Default Prefabs...` 才会带确认弹窗覆盖重建。新增界面时先在生成器里写默认布局，生成后在编辑器手调。

序列化约束（RETRO 教训）：每个挂 Prefab 的 MonoBehaviour 必须独占同名 .cs 文件。
