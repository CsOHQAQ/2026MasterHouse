## 1. 背景

该分支是旧框架时期的局外（out-game）玩法原型：先在 `web-demo`（Next.js 网页原型，合并时已剔除）验证交互与视觉，再逐步移植进 Unity。完整开发过程记录在 `Docs/归档/DEVELOPMENT.md`（工作单元流水），踩坑经验在 `Docs/归档/RETROSPECTIVE.md`（RETRO-001~017）。Prefab 编辑约定见 `Docs/PREFAB_UI_GUIDE.md`（仍然有效，未归档）。

## 2. 功能总览（玩家视角）

- **标题页**：主菜单（继续游戏/新游戏/读取存档/画廊/设置/退出），键盘 ↑↓/Enter 导航，网页版视觉复刻（字距、渐变、hover 动效）。
- **存档页**：3 个存档槽，新游戏与读档共用一套布局。
- **开门过场**：进入存档后 1.35 秒 DOTween 开门动画，然后进入 House Hub。
- **House Hub**：主界面。顶栏（DAY/时段/时钟/信用点）、当前访客任务卡、访客事件列表、右侧功能菜单、底部 4 房间导航（起居室/卧室/厨房/书房）、场景说明与设备热点。
- **系统面板**：11 类（委托/设备/日记/通讯录/档案/日历/仓库/设置/个人/商城），从右侧滑入。
- **访客系统**：4 位业务访客按各自拜访时间从大门走进起居室，常驻游走；点击触发对话，可完成服务/拒绝接待；另有 6 只"串门邻居"氛围 NPC 轮换进场、门口排队，可选择"请进屋/请回吧"（纯表现，无业务后果）。
- **家具摆放模式**：从 Hub 进入，收起全部 UI，在起居室内拖拽摆放/收纳/购买家具（网格吸附、占位预览、桌面家具级联）；退出后当前布局**烘焙成 Hub 背景图**，已摆家具生成可交互热点。
- **流通数值**：货币（服务收入→购买家具）、声望（服务加/拒绝减，同时是商城解禁门槛）、装饰分（派生展示值）。
- **加速游戏时钟**：现实 1 秒 = 游戏 1 分钟，驱动时段与访客进场；周结算跳到次日 08:00。
- **观景模式**：收起全部 HUD，拖拽平移、滚轮缩放看房；访客与热点跟随。
- **存档**：3 槽 PlayerPrefs 存档（v3），多处自动落档防丢进度。

## 3. 架构总览

整体是"**单例上帝控制器 + Prefab 视图组件 + 代码工厂兜底 + 静态数据/服务**"的原型架构：

```
OutGameUI（MonoBehaviour 单例，2869 行）────── 页面流转/输入/绑定/业务结算/存档，一手包办
  ├─ 视图层：OutGame*View.cs（约 24 个）      Prefab 上的纯序列化引用容器，无逻辑
  │          OutGameUIFactory（别名 F.）       运行时代码生成 uGUI 的控件工厂（Prefab 缺失时兜底）
  │          OutGameTweenButton / LetterSpacing 行为组件（DOTween 动效 / 字距）
  ├─ 数据层：OutGameUIData（静态硬编码配置 + OutGameSaveData 存档结构）
  │          FurnitureTable / FurnitureRoomTable / HouseEconomyConfig（三张 SO 配置表）
  ├─ 服务层：OutGameClock（静态时钟）、HouseEconomy（静态经济）、FurnitureSceneComposer（静态烘焙器）
  ├─ 子系统：OutGameVisitor*（访客表现层 4 脚本）、Furniture/（家具模式 12 脚本）
  └─ 编辑器：OutGameUIPrefabGenerator（28 个 Prefab 生成/修复）、FurnitureConfigSetupUtility（配置表生成）
```

模块间对接方式全部是**静态类 + 静态方法 + C# event + 回调 Action**，没有依赖注入、没有接口抽象。

## 4. 局外 UI 框架

### 4.1 启动与生命周期

- 入口 `OutGameUI.Build()`（`OutGameUI.cs:92`）：动态创建 Canvas（ScreenSpaceOverlay，sortingOrder 500，1920×1080 缩放基准）并 `DontDestroyOnLoad`。
- 原自动入口 `[RuntimeInitializeOnLoadMethod] AutoBuild()` 的方法体**已注释**（`OutGameUI.cs:89`），`HouseGmConsole.AutoBuild`（F1 GM 面板）同样已注释——两者当前都不会自动激活，场景文件中也没有挂载。
- `Start()` 兜底创建 EventSystem；`OnApplicationQuit` 在 Hub 内自动写档。

### 4.2 页面流转

三个整页视图 `View { Title, Opening, Hub }` + 面板/对话叠加层：

```
ShowTitle ──新游戏/读档──▶ ShowSavePage ──选槽──▶ EnterSlot ──▶ PlayOpening（开门过场）──▶ ShowHub
    │                                                                                  ├─ OpenPanel（11 类面板）
    ├─ ShowGallery / ShowTitleSettings / ShowExit                                      ├─ SelectGuest → ShowDialogue
    └─◀────────────── ESC（先自动写档）──────────────────────────────────────────────  └─ SelectRoom → SwapRoom
```

页面根切换统一走 `NewView()`（`OutGameUI.cs:221`）：Kill 旧 Tween → 销毁旧根 → 加载 Prefab（失败则代码兜底 + 警告日志）。输入为旧版 `Input` 轮询，集中在 `Update()`，ESC 按"对话→面板→Hub→标题"的优先级逐层退出。

### 4.3 Prefab 优先 + 代码兜底双路线（本框架最重要的约定）

分层原则："**Prefab 管布局，C# 管逻辑**"（详见 `Docs/PREFAB_UI_GUIDE.md`）：

- 28 个 Prefab 位于 `Assets/Resources/OutGameUI/Prefabs/`，与 `OutGamePrefabResourcePaths.cs` 的路径常量一一对应；每个 Prefab 根挂一个同名 `OutGame*View` 组件持序列化引用。
- 运行时优先加载 Prefab 并 `Bind*`（只填数据、挂事件）；Prefab 缺失时回退 `Build*` 代码布局（`OutGameUIFactory` 生成）。**同一份界面存在 Bind/Build 两套平行实现**，改内容需两处同步。
- 即使 Prefab 全齐，动态内容仍恒由代码生成：Toast、家具入口按钮、经济数值条、家具热点、访客舞台、开关门过场，以及仓库/设置/个人/商城/通讯录五个无 Prefab 的面板。
- 编辑器生成器 `OutGameUIPrefabGenerator`（`[InitializeOnLoad]`）**只补缺失、不覆盖手调**；`Tools/MasterHouse/OutGame UI/Rebuild Default Prefabs...` 才会带确认弹窗覆盖重建。附带 Missing Script 修复与 `OutGameTweenButton` 无损补挂。
- 序列化约束（RETRO 教训）：每个挂 Prefab 的 MonoBehaviour 必须独占同名 .cs 文件，否则域重载后变 Missing Script。

| 数据 | 位置 | 形式 | 内容 |

## 6. 游戏时钟（OutGameClock）

静态类，状态仅 `Day` + `MinuteOfDay`（float）。现实 1 秒 = 游戏 1 分钟（60×），一天 = 24 分钟现实时间，新一天从 08:00 开始。由 `OutGameUI.Update()` 在 Hub 视图内以 `Time.unscaledDeltaTime` 逐帧推进（家具模式期间继续走，标题/过场暂停）；`NextDay()` 供周结算；随存档 v3 序列化（`gameDay`/`gameMinute`）。

**注意**：日历面板是唯一仍读 `DateTime.Now` 的地方（渲染现实年月日 + 装饰性的"同步现实时间"按钮，按钮只弹 Toast 不改时钟），与游戏 Day 体系脱节，属遗留状态。

## 7. 访客系统（表现层）

四个 `internal sealed` 脚本，只做表现与点击转发，业务结算在 OutGameUI：

- **OutGameVisitorStage**：舞台层，仅起居室创建。业务访客按 `HourF >= visitHour` 进场（踩点半游戏小时内从大门走入，否则直接在屋内淡入——读档回来的情形）；邻居随机轮换、门口 3 个排队点动态补位；`LateUpdate` 按场景归一化坐标 × `uvRect` 换算锚点并按 y 深度排序（观景模式缩放平移天然跟随）。门口/游走坐标为硬编码常量，仅覆盖起居室。
- **OutGameVisitorActor**：单 NPC 状态机 `Hidden→Arriving→Waiting→Wandering→[Celebrating]→Leaving→Gone`，含深度缩放、名牌卡、邻居去留弹窗。
- **OutGameVisitorBubble**：头顶情绪气泡（♪？！…♥ 随机循环，内容随状态变化）。
- **OutGameVisitorSheetAnimator**：`RawImage.uvRect` 序列帧播放器，直接播 `{角色}_{await|attack}_sheet.png+json` 图集（素材来自 CatVsDog 项目，为占位美术），不切片。

业务流程：点击访客 → 服务窗口校验 → 对话层 → `ServeGuest`（+货币+声望，演员庆祝后离场）/ `RefuseGuest`（-声望，加速离场）→ 自动写档。`EndWeek` 周结算：每个未完成 -声望 → 清空本周状态 → `NextDay()` → 访客重新按拜访时间进场。注：拒绝也会置 `served=true`，`refused` 数组目前仅存档回读、无 UI 展示。

## 8. 家具系统（Assets/Scripts/Furniture，12 脚本）

- **入口**：Hub 右侧 dock 运行时追加的"家具摆放"按钮 → `FurnitureRoomController.Open(onClosed)`（静态单例守卫）。打开时**禁用整个局外 Canvas**，关闭回调里恢复 Canvas → 自动写档 → 重烘焙背景。舞台建在 `(500,0,0)` 远离节点玩法棋盘。当前**硬编码只取 rooms[0]**（起居室）。
- **场景组装**：三层背景（清晰底图 / 常驻远景模糊 / 拖拽时淡入的整幅失焦层，模拟景深）+ 透视相机 `FurnitureCameraRig`（FOV25，鼠标视差微转 + idle 漂移，无缩放）+ 若干 `FurnitureRuntimeGrid`（纯 C# 类，字典占位表）。
- **摆放交互**：表面类型（地面/桌面/壁挂）硬约束吸附；多网格择近 + 占位检测 + 绿/红预览；带桌面格的家具（茶几）摆放时动态注册 `tbl_{id}` 子网格，移动跟随、收纳级联；层级 = 底边深度行决定 sortingOrder 与视差 Z；点选为纯数学包围盒命中（无物理碰撞体）；双击快速收纳。
- **背景烘焙 FurnitureSceneComposer**：静态类，`Graphics.DrawTexture` 同步合成"干净背景 + 当前摆放"到 RenderTexture，作为 Hub 起居室背景；`GetPlacedFurniture()` 输出归一化矩形供 Hub 建悬停/点击热点。锚点数学在 Composer 与 Controller **两处独立重复实现**，修改必须手工同步（代码注释已声明此约束）。
- **HUD**：`FurnitureRoomHud` 为纯 C# 类运行时构造 uGUI（原型状态，未 Prefab 化），收纳栏按表面类型分三组，槽位四态（可用/已摆放/锁定/？未解禁）。
- **GM 控制台 HouseGmConsole**：F1 面板（加货币/声望/装饰分、全量重置），**当前入口已注释停用**。

## 9. 流通数值（HouseEconomy）

静态类，纯事件驱动（无 Update、无时间依赖），`Changed` 事件通知三处订阅方（OutGameUI 顶栏、家具 HUD、GM 面板）。三值模型：

| 值 | 来源 | 去处 | 默认参数 |
|---|---|---|---|
| 货币 | 完成服务 +320 | 商城/家具购买 | 初始 2480 |
| 声望 | 完成服务 +25 | 拒绝 -15、周结算每项未完成 -30（下限 0） | 初始 40；同时是家具"？"解禁门槛 |
| 装饰分 | 派生值：房间×50 + 设备×30 + 家具装饰分 + GM 加成 | 无 | 纯展示，不影响任何收益 |

购买是"声望解禁 + 货币足额"双门；`price≤0` 的家具视为初始拥有（读档时强制补齐，防改表丢家具）。快照 `Capture/Restore` 随存档序列化。访客消费、家具影响收入等玩法**不存在**。

## 10. 存档体系（v3）

- 介质：`PlayerPrefs`，key = `"MasterHouse.OutGame.Save." + 槽位(1..3)`，`JsonUtility` 序列化。
- 结构 `OutGameSaveData`：`version`（2=经济+家具布局；3=+时钟+访客到访）、房间、`served/refused/guestArrived[4]`、`gameDay/gameMinute`、音量/窗口设置、`savedAt` 时间戳（`DateTime.Now`）、经济快照、`hasFurnitureLayout` + 摆放列表（`hasFurnitureLayout` 区分"摆空了"与"从未编辑"）。
- 读档逐版本降级兼容，旧档回落默认值。
- 自动写档点：Hub 内每 60 现实秒、退出游戏、Hub 回标题、完成/拒绝服务、周结算、商城购买、家具模式退出、GM 重置。设计动机：时钟是持续流动的状态，只靠事件节点写档会丢挂机进度。

## 12. 已知问题与技术债

来自代码走读与对方遗留文档的汇总（不含"与新架构的差距"，那部分见下节）：

1. `HouseEconomyConfig.asset` 未创建，经济参数走代码默认值（菜单 `MasterHouse/家具系统/创建配置表` 可补）。
2. 日历面板读 `DateTime.Now` 渲染现实日历，与游戏 Day 脱节；"同步现实时间"按钮是纯装饰。
3. 家具锚点数学在 Controller/Composer 双实现，需手工保持一致。
4. 家具系统单房间硬编码（`rooms[0]`）；房间表的 `startCredit` 字段无人读取（货币初值实际来自经济配置）。
5. 访客门口/排队/游走坐标、访客配置、设备数据全部硬编码，未配置表化；动物素材为占位（猫狗 ↔ 狐鸦兔猬不对应），无行走动画。
6. 对话层的"家具快捷栏"与真实家具布局无数据联系（纯表现）。
7. 家具模式 HUD 未 Prefab 化；家具模式内无法保存（Canvas 被禁用，依赖退出时落档）。
8. Bind/Build 双路线导致每个界面两套实现，内容修改需双写。
9. 家具模式内的 DOTween 未 `SetUpdate(true)`，会受 `Time.timeScale` 影响（局外 UI 部分已统一 unscaled）。
10. "结束本周"语义实际是"跳到下一天早晨"，周/天概念未统一。
