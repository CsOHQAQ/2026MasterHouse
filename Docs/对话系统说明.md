## 1. 一句话概括

对话内容的唯一编辑源是 **`Excel/对话表.xlsx` 一张表**，导表整表重建成一个 `DialogueTable.asset`；
判定与结算逻辑写在代码里的**两张函数字典**，Excel 只填函数名。改台词不碰代码，加判定才碰代码。

```
Excel/对话表.xlsx（唯一源，三页：对话组 / 对话内容 / 参考）
  └ Tools/导表/export_dialogue.py → Assets/Configs/对话组表.csv + 对话内容表.csv
       └ DialogueCsvImporter（整表重建，有错就整体不落盘）
            └ Assets/Resources/OutGameUI/DialogueTable.asset
                 ├ groups  : List<DialogueGroup>      { id, steps }
                 └ entries : List<DialoguePoolEntry>  { groupId, raceId, needId, category, conditions }
```

散资产（一组一个 `.asset`）已整体退役——Excel 成为唯一源之后，diff 友好/多人并行/拖拽引用三条理由全部失效，
而删一行留一个孤儿 `.asset`、改一次 ID 多一份垃圾的代价是实打实的。整表重建把这些一次消掉。

**双击 `Tools/导表/export_config.bat` 导表**，Excel 是唯一编辑源，直接改 CSV 会被覆盖。

## 2. 八个对话分类（`EDialogueCategory`）

| key | 中文 | 触发时机 | 代码位置 |
|---|---|---|---|
| `firstMeeting` | 初次见面 | 首次点击前台**队首**访客 | `VisitorManager.RequestTalk` |
| `waitingReception` | 等待接待 | 同一位前台访客的二次点击（`MetPlayer` 已置位） | 同上 |
| `needTalk` | 需求对话 | 入住并**已开口示意**后点击他 | 同上 |
| `feedbackDisappointed` | 需求反馈·失望 | 服务超时 | `SettleNeedResult` |
| `feedbackPlain` / `feedbackFine` / `feedbackPerfect` | 需求反馈·一般/还行/完美 | 结算档位 | 同上 |
| `smallTalk` | 闲聊 | 停留期冒泡（场景气泡，不开模态、不碰闸门） | `TickStates` |

- **枚举值显式赋值、新增只能追加**：值参与派生种子，改动会让同一 `runSeed` 下抽到的对话变掉。
- Excel 里填**英文 key**（从数据校验下拉里选），中文名只出现在报错与日志里；导入器也认中文名，方便粘贴。
- **没有独立的「被拒绝」分类**：拒绝的台词是【初次见面】/【等待接待】里那个「拒绝」选项的子句。
- **没有独立的「验收」分类**：验收就是【需求对话】里那个挂 `RoomHasNeedFurniture` 的选项——
  一次点击既听需求又能交付，比拆成两类少一半配置量。

## 3. 结构

```
DialogueGroup
  └ steps: List<DialogueStep>          主线
       kind = Line | Action | Branch
       └ options: List<DialogueOption> （kind == Branch）
            ├ conditions: List<DialogueCall>
            └ steps: List<DialogueSubStep>   子句，只能 Line | Action
```

- `DialogueSubStep` 是独立类型而不是复用 `DialogueStep`——**嵌套分支明确不做**，类型上就堵死；
  顺带避开 Unity 的「Serialization depth limit exceeded」递归警告。
- 选项子句播完 → **汇合到主线的下一步**。分支放在组尾时「汇合」天然等于「结束」，所以没有 `End` 标记。
- **跨组跳转不做**（`next` / `nextGroup` / 成环检测整套已删除）。真需要时做成一条 `JumpToGroup(id)` 事件即可，是纯增量。

## 4. 条件与事件：函数注册表（零反射）

`Assets/Scripts/Dialogue/DialogueFuncs.cs` 里两张字典是**唯一真相源**——导表校验、Excel 模板的下拉、
资产校验器全部从这里取，一处维护三处生效。Excel 里写 `DayAtLeast(3)`，**导入期**由 `DialogueCallParser`
解析成 `DialogueCall { func, args[] }` 存进表，运行时查字典直接调委托。

没有 `TypeCache` 扫描、没有 `Delegate.CreateDelegate`、没有 IL2CPP 裁剪风险。
改函数名也不再是高危操作：数据里存的是名字字符串，改类名只要同步改表 + 重导一次。

**条件（8 条，纯查询、不得有副作用——选项置灰会反复求值）**

| 函数 | 参数 | 语义 |
|---|---|---|
| `HasEmptyRoom` | — | 还有空客房（只看房，不看队列） |
| `CanAcceptGuest` | — | 现在能接待新客人（有空房 **且** 没有别人正在等分房） |
| `RoomHasNeedFurniture` | — | 所住房间摆着他要的家具之一（条件类需求的验收判据；不是条件类需求一律 false） |
| `DayAtLeast` | 天数 | 第 N 天或更晚 |
| `CurrencyAtLeast` | 数量 | 货币不少于 N |
| `ReputationAtLeast` | 数量 | 声望不少于 N |
| `SatisfactionAtLeast` | 档位 | 本次满意度不低于指定档（结算之后才有意义） |
| `VisitorStateIs` | 状态 | 访客处于指定状态 |

多条之间是 **AND**（`;` 分隔的隐式列表，不是表达式语言）；OR / NOT 与表达式语法明确不做。
函数名未注册时**报错并按不通过处理**（宁可少说话，不可乱结算）。

**事件（7 条）**

| 函数 | 参数 | 语义 | 奖励类 |
|---|---|---|---|
| `Accept` | — | 接待（转「等待分配房间」，此时不说需求） | |
| `Reject` | — | 拒绝（扣声望并离场） | |
| `CompleteNeed` | 档位，留空=perfect | 完成需求结算（条件类固定完美；小游戏类由分数定档） | ✅ |
| `StartMinigame` | — | 开始小游戏（只登记意图，见下） | |
| `AddCurrency` | 数量 | 增减货币（正给负扣，下限 0） | ✅ |
| `AddReputation` | 数量 | 增减声望（正给负扣，下限 0） | ✅ |
| `Log` | 文本 | 往 Console 打日志（自查分支走向用） | |

两条铁律：

1. **事件只做一次性的状态转换与结算，绝不承担「必须发生的后续推进」。**
   拒绝事件只置状态，离场由状态机自己走完——把「离场」挂在对话末尾的话，玩家一按 ESC 访客就永远卡在场上。
2. **奖励类事件（`IsReward`）只允许放在所在路径的最后一个事件位**（主线末尾 / 某个选项子句末尾）。
   中途给奖励 + 玩家 ESC = 这段视为没播过、再抽到又领一次。校验器据此给警告。

> ⚠ `StartMinigame` **只登记意图、不当场打开页面**：它在播放推进过程中执行，此时对话层还在栈顶，
> 当场 `PushOverlay` 会让随后的收框弹掉小游戏层而不是对话层。真正开页由 `HubPage.OnDialogueEnded`
> 调 `MinigameOverlay.ConsumePending`。
>
> `StartMinigame` **不带参数**：开哪个小游戏、打哪一关都从访客当前需求（`MinigameNeedDef` 的
> `minigame` / `level`）上读，对话表里不写死任何关卡（架构设计 §8.4 选关）。所以同一条
> `Action | StartMinigame` 行对所有小游戏类需求通用，换关卡只改需求资产。

## 5. 抽取规则

```
候选 = 表[种族][分类] → 需求筛选（专属优先）→ 条件筛选 → 排除 recent 环
候选被 recent 排空 → 清环重筛（保证永远有话可说）
种子 = Hash(runSeed, 访客实例Id, 分类, 本次请求序号)，候选内**等权**随机
```

- **需求维度是「专属优先」而不是「混着抽」**：策划特地为某条需求写了台词，就该说那个，
  不该有一半概率被通用句盖过去。想要变化就给同一条需求多写几组。
- `needTalk` 的**需求ID 列必填**（导表期报错）；四档反馈**选填**（填了即专属）；其余三类**必须留空**。
- 候选顺序 = Excel 行序（稳定可复现）；`MetPlayer` 与 recent 环**不进存档**（对话侧只留接缝，待定 #9）。
- **ESC 中断视为这段没播过**：不写 recent、`MetPlayer` 不置位，下次仍可能抽到同一组。

## 6. 「点了没反应」的三道防线

对话是内容驱动的，内容缺了不该表现成「游戏坏了」。三处各管一段：

1. **导表期**（`DialogueCsvImporter`）——函数名、参数个数、分类、`needTalk` 的需求ID 必填、分支无条件选项，
   写错当场报 Excel 行号，且**整表不落盘**（半张表比没有表更难查）。
2. **校验器**（`DialogueAssetValidator`）——**覆盖度问题一律是警告而不是错误**：
   某条需求没配 `needTalk`、某个种族缺分类，都只 `LogWarning`。
   理由是错误会让整表不落盘，新建一个 NeedDef（哪怕只是试验用）就把已调好的台词一起废掉，
   而"某位访客没话说"根本不影响其余内容跑起来。
3. **运行时**——`IDialogueService.RequestVisitorDialogue` **返回 bool**，`HubPage.SelectGuest`
   在没播出来时给一句「他现在没什么想说的 · 对话表里缺内容，详见 Console」。

另外 `DialogueManager.AbortForMissingUi()` 兜住表现层拉框失败的两个出口（Prefab 缺失 / 组件不对）：
`TryBegin` 是**先关闸门再广播 `PlaybackStarted`** 的，框没开出来就没人会调 `Close`，
`ModalDialogue` 那条停走原因会把时间永久冻住。

## 7. 与访客状态机的联动

```
投放：日程到点 + 前台额度 2（FrontDesk + AwaitingRoom）+ HasFreeRoom
【FrontDesk】只有**队首**且 CanAcceptGuest 时可交互（有提示、点得动）
    点击 → 初次见面（首次）/ 等待接待（MetPlayer 已置位）
    等搭话超时 → 直接离场，**不播对话、不扣声望**，只计一次流失
    打烊 → EndDay 自动清场
【AwaitingRoom】最多 1 位（CanAcceptGuest 串行化）；无对话；**唯一阻塞【结束今天】的状态**
    刻意不给拒绝出口：接待那一刻已经保证有房，他一定分得到，所以不会死锁
【Serving ①安顿中】ScheduleNeedPrompt 排一个随机 tick；点他只有 Toast
【Serving ②已示意】头顶/卡上亮提示；**服务超时从这一刻起算**
    点击 → 需求对话（说需求 + 交付/推迟/放弃）
    交付 → CompleteNeed → 反馈档 → 转停留
    超时 → 反馈·失望 → 转停留，**不扣声望**
【Wandering】停留时长起算；闲聊冒泡；到点离场。**跨天不 roll**
所有计时按 BusinessTick：打烊停表、次日续算
```

几处容易踩的点：

- **`CanAcceptGuest = HasFreeRoom && !HasAwaitingRoomVisitor`**。只看 `HasFreeRoom` 会出现
  「3 房住满 2 间、前台 2 人，两个都接待成功、第二个再也分不到房」的死锁。
- **投放仍用 `HasFreeRoom`**（不串行化）：门口本来就允许排队，前台额度管上限。
- **进屋不再自动弹对话**。自动弹会在玩家逛商店 / 摆家具时冷不丁盖上来（那两处时钟照走），
  而家具模式还禁着整个壳 Canvas——那会变成「看不见的对话框 + 关不掉的闸门」，是硬卡死。
- **`MetPlayer` 在【初次见面】正常播完时才置位**（ESC 中断视为没播过，下次仍播初次见面）。

### ⚠ 写【初次见面】/【等待接待】时必须留一个「不动手」的选项

这是最容易踩、而且**踩了完全没有报错**的一个坑：

`MetPlayer` 只在【初次见面】正常播完时置位。而如果这一组的所有选项都会让访客离开前台
（接待 → 待分房、拒绝 → 离场），那就永远不存在「前台 + 已打过招呼」的实例，
**【等待接待】这一整类抽不到**——台词写了，玩家一辈子听不见。

所以【初次见面】里必须有一个「什么都不做但正常收尾」的选项（模板里那句「（先想一下）」）。
`make_dialogue_template.py` 的种子内容与 `Excel/对话表.xlsx` 的组 10001 都已经带上。
校验器**没有**拦这一条（判定它需要跨模块推理，做成静态规则性价比不高）。

## 7.5 表现层：2.0 美术换代（2026-08-19）

对话层的界面已按 2.0 设计图整层重做（版式与坐标见 `Docs/局外系统说明.md` §5.4）。
对**规格**有影响的只有一条——**旁白句不再是「居中无框」**：

> 归档设计说明 §4.1 定的是「访客句 = 立绘 + 名字条；玩家句 = 无立绘、另一种框；旁白句 = 居中无框」。
> 2.0 起旁白句**复用同一块对白板**，只是名字凸台留空、正文改居中对齐。
> 两个原因：名字凸台是烘在 `对白底板` 素材里的，切不出「只藏名字」的版本；
> 新底图是明亮水彩外景，无框墨字直接压在天空/建筑上读不清。
> 「没有名字 + 正文居中」照样和访客句、玩家句区分得开。

三种说话人的现行表现：

| 说话人 | 立绘 | 名字凸台 | 正文 |
| --- | --- | --- | --- |
| 访客 | 显示（按立绘ID 取图） | 访客名，墨蓝 `#5676A6` | 左上对齐 |
| 玩家 | 显示（按立绘ID 取图） | 玩家名，暖褐 `#9C6238` | 左上对齐 |
| 旁白 | 不显示 | 留空 | **居中对齐** |

底部三颗键位条（ESC 返回 / 中键 切换选项 / space 确认）是**真按钮**，
点击等价于对应按键，鼠标党不必去够键盘；输入本体仍在 `DialogueHotkeys`。

## 7.6 玩家身份：羊族即玩家（2026-08-19）

羊族（`Race_goat`，显示名「嘻洋羊」）被定为玩家角色——旅馆老板。
名字凸台上原先写死的「我」换成她的名字，**名字取自访客种族资产的显示名，对话侧不另存一份**；
玩家是哪个种族配在 `DialogueTuningConfig.playerRace`（现指向 `Race_goat`），留空则回落旧口径「我」。
改老板的名字 = 改 `Excel/访客种族表.xlsx` 里 goat 那一行，不碰代码。

连带改掉的是**玩家句不再藏脸**：上表原本定「玩家句 = 无立绘」，那是老板还不是个有脸的角色时的口径。
现在立绘显隐**只看对话表里配的立绘ID**（查不到图就整个隐掉，不留白板），与说话人无关；
唯一的例外是旁白——它是环境描写、没有说话的人，让承接来的上一张脸留在屏幕上只会读成「还是他在说」。
导表期那条「说话人不是 visitor 却填了立绘ID」的警告随之放宽成只拦旁白。

判断「这句是谁在说」有两条判据，都在 `DialogueManager.IsCurrentLineFromPlayer`：

1. 说话人 = `player`——正规写法；
2. 说话人 = `visitor` 但立绘ID 是 `goat_*`——**临时桥接**。

第二条对着的是对话表现状：老板的台词（165 行）全部写在 `visitor` 上——彼时玩家句会藏脸，
而她要露脸，只能借访客的壳。结果名字凸台去取"当前访客"的名字，画面上就成了「猫的名字 + 羊的脸」。
表还在策划手里编辑，这轮不动表、先在表现层把名字认回来。

于是**立绘只看立绘ID、名字与名字配色只看「谁在说」**，两者都不再由说话人枚举直接决定。
立绘表不带种族列（那张表刻意不区分角色），前缀 `种族id_差分` 是现有数据唯一的可用线索——
现表 367 条内容里，填了说话人的 338 条立绘ID 无一为空、前缀全是 8 个种族id 之一
（另 29 条是分支子句的续行，说话人与立绘ID 都留空），判据成立。

等对话表改成「说话人 = `player` + 保留立绘」之后，判据 ② 与本节可以一并删掉；
`playerRace` 这个配置项要留着——那时名字仍然从它取。

## 8. 明确不做

- 嵌套分支（子句里再出 Branch）、跨组跳转、分支子句的 `End` 标记、对话组权重
- 条件的 OR / NOT 组合与表达式语法
- 具名客人的专属对话（`NamedVisitorDef` 现阶段无内容）
- 对话系统的存档接入（只留接缝，待定 #9）
- 场景演员头顶的感叹号图标（**目前只有访客卡的角标**：世界空间标记要动 Prefab 与美术资源）

## 9. 已知内容缺口（2026-08-16）

覆盖度本身已经补齐：2026-08-16 访客阵容换成美术交付的 8 个角色
（`rabbit / goat / wolf / leopard / cheetah / ox / cat / yak`）时，
原先只有 `fox` 一族的那 12 组对话按种族复制了 8 份，
`Assets/Configs/对话组表.csv` 现有 **96 组**，每个种族都点得开、不会再走到
第 6 节第 3 道防线的「他现在没什么想说的」。对话组ID 的**百位是种族序号**
（rabbit=0 → `10001/20001/30001…`，goat=1 → `10101/20101/30101…`，依此类推）。

缺的是**文案本身**：8 份内容目前是同一套文本，只有立绘ID 各顶各的脸，
角色之间还没有性格差异。**文案填充由他人在 `Excel/对话表.xlsx` 里进行**，不在当前开发待办里。

## 10. 代码位置

`Assets/Scripts/Dialogue/`（13 个 + Editor 2 个）：

- 内容：`DialogueTable` / `DialogueData`（`DialogueGroup` / `DialogueStep` / `DialogueOption` / `DialogueSubStep`）/ `DialogueLine` / `DialogueCategory` / `DialogueTuningConfig`
- 条件与事件：`DialogueFuncs`（两张字典）/ `DialogueCall`（调用结构与解析）/ `GameplayContext`
- 业务：`DialogueManager` / `DialogueRuntime`
- 文本：`DialogueTextFormatter`（`{需求}` 直取 `Need.description`）
- 访客侧接缝：`IDialogueService`（fire-and-forget，返回 bool）
- 编辑器：`Editor/DialogueCsvImporter`（导入器）、`Editor/DialogueAssetValidator`（校验器）
  ——**编辑器窗口与 `[SerializeReference]` 抽屉已整体退役**，Inspector 不再是编辑入口
- 表现层：`HouseUI/DialogueOverlay` / `DialogueTypewriter` / `DialogueHotkeys`
