# 测试场景需求记录

> 2026-08-07 讨论定稿。本文档是测试场景落地的需求依据，与《架构设计.md》配合阅读；冲突时以《架构设计.md》为准。

## 一、目标

1. **策划玩法验证**：读取已有节点/关卡配置，可选关、可热重载切关；关内可自由生成/移除节点、连线并观察产出。
2. **数据结构验证**：整个流程尽可能贴近真实游戏的初始化与推进逻辑（LoadLevel → tick 三阶段 → View 全量重建）。debug 工具可以有，但核心逻辑必须留在框架内。

### 调试面板能力清单

- **权限模型**：默认走真实规则（生成列表 = 本关 BuildableNodes，受 CanBuild 数量上限约束，预置节点 CanMove/CanDelete 生效）；「自由模式」开关打开后列出项目全部 NodeDef、无视数量上限与预置约束。自由模式只绕过 Controller 层资格校验，**放置合法性仍走 CanPlaceNode**，不产生脏状态。
- **时间控制**：暂停 / 单步 tick / 倍速（0.5x、1x、2x、4x、8x）。GameManager 需补对应 API（累积器乘系数、单步喂一个 tick）。
- **数据展示**：当前关名、TickCount、PlayerCargo 清单（产出验证出口）、选中对象详情（选中连线时显示状态/持货槽/节拍与在途计时）。
- 不做：PlayerCargo 作弊增删（v1 仓库只进不出、建造免费，无消费场景）。

## 三、实现要点

- **Manager 广播事件**：落地 §2.1 已定稿的结构变化粗粒度通知（节点/链接增删、节点移动、关卡 Load/Unload），Manager 完成修改后广播、携带数据对象引用。这是框架的一部分，不是 debug 代码。View 同时保留「读档/Load 全量重建」路径为真相源。
- **连续量轮询**：NodeGO 每帧读暂存量/配方进度（头顶世界空间文字，用 VisualAssets）；TransferPulseGO 按 `TransitCounter/TransitTicks` 沿 PathCells 折线插值，Blocked 停在目标门口；LinkGO 按 §6.5 状态配色。
- **连线失败反馈**：`TryCreateLink` 的 `failReason` 必须在界面上显示（临时消息即可），策划连不上线时要能知道原因。
- **断线处理**：无理线功能期间，断线（红色）靠删除重连解决；可选做一个 debug「重新布线」按钮（对选中断线链接删除+同 Pin 重建走 A*），属 debug 便利，不违反「无自动修复」原则。
- **非法临时态表现**：最简着色提示（如红色 tint）即可，正式交互仍属待定 #14。
- **场景文件**：新建独立测试场景（不复用 SampleScene）。GameManager 的 startLevel 字段保留可空，加载由调试面板驱动。
- 拾取/交互全部经 Manager 修改数据，View 只读（§2、§11.4）不因 debug 场景放松。
