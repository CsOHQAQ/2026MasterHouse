## 1. 一句话目标

把现状「4 句写死台词 + 一个单方法接缝」做成**自研的分支对话系统**：单句 / 事件 / 分支组成对话组，对话组按种族与触发分类进池，事件可驱动业务状态。

## 3. 结构总览

```
Model（Def，运行时只读）
  DialogueGroupDef      一个对话组一个 SO 资产
  DialoguePoolDef       一个种族一个 SO 资产；8 个对话组列表 + 4 个预览单句列表
  DialogueTuningConfig  全局：打字机速度、recent 环长度 N、气泡时长等

  内联结构（非 SO）
    DialogueLine        说话人 / 文本 / 表情
    DialogueStep        Line | Action | Branch 三选一
    BranchOption        条件 / 选项文本 / 事件 / 跳转
    IGameplayAction     [SerializeReference] 多态事件
    IGameplayCondition  [SerializeReference] 多态条件

ViewModel
  DialogueData          recent 去重环 + Capture/Restore 接缝
  DialogueManager       选取、播放推进、事件执行、闲逛冒泡调度（挂全局 tick）
  DialogueRuntime       单次播放的运行状态（当前组/步/延迟队列）

View
  DialogueBoxView       新建 Prefab：立绘位 + 名字条 + 文本区 + 选项列表
  OutGameVisitorBubble  扩展：显示闲逛台词与交付预览单句
```

目录：`Assets/Scripts/Dialogue/`，命名空间 `MasterHouse`（§15.1）。

**关于事件系统的泛用性**：`IGameplayAction` / `IGameplayCondition` 的接口形状不依赖对话上下文，但**本期仍放在 `Dialogue/`**。等出现第二个消费方（成就、任务、家具解禁）时整体平移进 `Core/`——同一命名空间下这是零成本操作，符合 §15.3「不预设抽象」。

## 4. 数据结构规格

### 4.1 DialogueLine（单句）

```
speaker     枚举：访客 | 玩家 | 旁白
text        string（支持占位符，§9）
portraitId  string   ← 仅 speaker==访客 时生效，查 PortraitTable 取图
```

表现区分：访客句 = 立绘 + 名字条；玩家句 = 无立绘、另一种框；旁白句 = 居中无框。

> **修订（2026-08-14，立绘 ID 化）**：本节原文写的是 `emotion  EDialogueEmotion ← 索引种族的立绘差分表`，
> 并配「差分缺失时回退到默认表情并 LogWarning，不阻断播放」。该条**已作废**，改为：
>
> - 表情枚举 `EDialogueEmotion` 整体退役。枚举的前提是差分能归类，而美术要求的差分归不了类。
>   立绘改成一张 ID → 路径的索引表（`Excel/立绘表.xlsx` → `PortraitTable`），加差分 = 加一行。
> - **留空 = 沿用上一句**（GVN 惯例），组内首句留空则用该访客种族的「默认立绘ID」。
>   承接在播放期做（`DialogueManager.CurrentPortraitId`）——分支汇合回主线时该顶哪张脸
>   取决于玩家选了哪个选项，导表期静态展不开。
> - 回退逻辑撤掉，改为**导表期硬校验**：对话表引用的立绘ID 必须存在于立绘表，否则整表不落盘。
>   运行时不再有「缺差分」这种状态。
> - 连带作废「一组台词多种族共用」：枚举是种族无关的键，具体 ID 不是。
>   对话表第一页的「种族」列不再接受「通用」与 `/` 多选，**一个对话组只属于一个种族**。

### 4.2 事件与条件（[SerializeReference] 多态）

```csharp
public interface IGameplayAction
{
    /// 中断（ESC）时，尚未执行到的本事件是否仍要补执行
    bool ExecuteOnInterrupt { get; }
    void Execute(GameplayContext ctx);
}

public interface IGameplayCondition
{
    bool Evaluate(GameplayContext ctx);
}
```

- 序列化形态见 §11 的编辑器要求；具体类是普通 `class` + `[Serializable]`，**不受「MonoBehaviour 必须独占同名文件」那条约束**（那条只针对 `MonoBehaviour`/`ScriptableObject`），可按分类合并到少数几个文件里。
- **类改名必须挂 `[MovedFrom]`**，否则策划已配的数据会被静默清空。这是本方案唯一的高危操作，写进代码注释。
- 多个条件之间默认 **AND**。需要 OR/NOT 时再加 `OrCondition`/`NotCondition` 组合子类，现在不做。
- `GameplayContext` 持有各 Manager 引用 + 当前访客实例 id；字段可空，非访客场景留空。

### 4.3 DialogueStep 与 BranchOption

```
DialogueStep = Line | Action | Branch（三选一）

BranchOption
  conditions   [SerializeReference] List<IGameplayCondition>   空 = 无条件
  text         选项文本
  actions      [SerializeReference] List<IGameplayAction>
  next         枚举：继续本组 | 跳到组 | 结束
  nextGroup    DialogueGroupDef      ← next==跳到组 时才填
```

- **跳转不使用任何位置寻址**：没有行索引、没有标签。插行删行绝对安全，组内不可能成环。
- 分支**可以出现在 steps 的任意位置**，不限于末尾。「分支后各说各的再汇合」的写法是：两个选项跳到不同组，那两个组末尾再跳到同一个汇合组。
- **硬校验：每个 Branch 至少有一个无条件选项**（防止条件全不满足时卡死）。编辑器与资产校验器都要拦。

### 4.4 DialogueGroupDef（SO，一组一资产）

```
steps: List<DialogueStep>
```

存放路径 `Assets/GameData/Dialogue/<种族>/`。选择独立资产而非 sub-asset 的理由：diff 友好、多人并行写台词不冲突、Unity 原生的拖拽引用与「查找引用」直接可用。**配置时的聚合浏览由编辑器窗口解决**（§11），不靠文件结构。

### 4.5 DialoguePoolDef（SO，一种族一资产）

```
Entry = { DialogueGroupDef group, int weight }

初次见面:        List<Entry>
开始等待服务:    List<Entry>
被拒绝:          List<Entry>
完成服务_不对味: List<Entry>
完成服务_一般:   List<Entry>
完成服务_满意:   List<Entry>
完成服务_完美:   List<Entry>
满意后闲逛:      List<Entry>

交付预览_不对味: List<DialogueLine>    ← 单句，非对话组
交付预览_一般:   List<DialogueLine>
交付预览_满意:   List<DialogueLine>
交付预览_完美:   List<DialogueLine>
```

- 八个具名字段而非分类数组：Inspector 一目了然，缺哪个一眼看出，且不需要写重复键/缺键校验。
- **交付预览存的是单句不是对话组**，所以从类型上就挂不了事件与分支——「预览绝不结算」是类型保证的，不是靠约定。
- 某个列表为空时：`LogError`（指名种族 + 分类）但**不阻塞业务**，跳过对话直接走后续流程。缺台词不该卡死接待。

### 4.6 DialogueData（ViewModel）

```
recent: (raceId, trigger) → 定长环形队列(N)     ← N 配在 DialogueTuningConfig
Capture / Restore                              ← 存档接缝，当前无调用方（待定 #9）
```

只能被 `DialogueManager` 修改（§11.4）。用 `Dictionary` 做键查询不违反 §11.2——那条禁的是**依赖枚举顺序**，这里只做查询与入队出队，从不遍历。

## 5. 播放器语义

### 5.1 推进

- 进入 `Line`：逐字显现（打字机，速度配在 `DialogueTuningConfig`）。
- 点击：文本未显完 ⇒ 立即全文；已显完 ⇒ 下一 Step。
- 遇 `Branch`：出选项，**必须选**（不满足条件的选项置灰并显示原因，或直接隐藏——【待确认】默认置灰）。
- 遇 `Action`：按 §5.3 执行，然后继续下一 Step。
- 打字机是**表现层计时**，可用 `deltaTime`；不进 tick 逻辑（模态期间 tick 本来就停了）。

### 5.2 中断（ESC / 关闭按钮）

- **对话可以随时退出，且视为这段对话没有被播放**：不写入 `recent`（下次仍可能抽到），业务不进入任何新状态。
- 已经执行过的事件**不回滚**（既成事实）。
- 尚未执行到的 `Action`：中断时遍历剩余 steps，**只补执行 `ExecuteOnInterrupt == true` 的那些**，其余丢弃。
- 对话层是唯一带关闭语义的叠加层，仍走 `HouseUIManager` 的退栈；不需要为它改 ESC 优先级。

### 5.3 两条铁律

1. **对话事件只做一次性的状态转换与结算，绝不承担「必须发生的后续推进」。** 例如 `RejectVisitor` 只把访客状态置为「已拒绝」，**离场由访客状态机在 tick 里自己走完**。绝不能把 `LeaveVisitor` 挂在对话末尾——玩家一按 ESC 访客就永远卡在场上。`ExecuteOnInterrupt` 是补丁，状态机自洽才是根本。
2. **奖励类事件只允许放在对话组末尾或分支选项上。** 中途给奖励 + 玩家 ESC = 反复领取。编辑器给**提示性校验**（放错位置警告，不阻断）。

## 6. 选取规则

```
候选 = 池[种族][分类].筛(所有条件通过).排除(recent[种族,分类])
       若候选为空 → 清空该键的 recent 重新筛（保证永远有话可说）
种子 = Hash(runSeed, 访客实例Id, 触发分类, 本次请求序号)
选中 = 按 weight 加权抽一条
正常播完 → 写入 recent 环        ← 中断则不写（呼应 §5.2「视为未播放」）
```

- 随机源与访客系统同一套**派生种子**（无状态、可复现、读档不刷），实现细节见访客交付说明 §6.1。
- **交付预览单句的种子不同**：`Hash(runSeed, 访客实例Id, 提交物品Id, 档位)`。这样同一件物品反复拖入拖出，反应稳定不闪烁。预览不参与 `recent`。

## 7. 触发点与业务契约

**访客 → 对话**（访客状态机在转换点请求）：

| 触发分类 | 时机 | 通道 |
|---|---|---|
| 初次见面 | 玩家点击前台等待接待的访客 | 模态对话框 |
| 开始等待服务 | 接待成功、进入服务中（含程序化需求句 §9） | 模态对话框 |
| 被拒绝 | 玩家拒绝 / 等搭话超时 / 等交货超时 | 模态对话框 |
| 完成服务 | 提交结算后，按 `EServeSatisfaction` 选组 | 模态对话框 |
| 满意后闲逛 | 闲逛期间由冒泡调度器定期请求 | 场景气泡 |
| 交付预览 | 物品放入交付框时（单句，不结算） | 场景气泡 / 页面内气泡 |

VisitorManager.Submit(instanceId, ItemDef)
EconomyManager.*                      （货币/声望）
…后续按需扩展 IGameplayAction 子类

## 8. 时间与闸门

- **模态对话框开启期间关闭营业闸门**：局内生产停 tick、局外时钟停走、访客各类倒计时停表。因此「等对话播完」是免费的——`RequestDialogue` 是 fire-and-forget，不需要回调、不需要协程（协程状态无法序列化，与 §11 冲突）。
- **场景气泡不碰闸门**（闲逛台词、交付预览都是环境表现）。
- **闸门必须改成原因集合**：现在 `HouseClockManager.SetRunning(bool)` 是单一布尔，改为「任一原因存在即关闸」，否则后关的会把先关的覆盖掉。
- **2026-08-12 核查修正**：原文说「持有者已有三个」不准确——打烊在访客重做里落地为 `IsClosedForToday`（时间的纯函数派生），不是 `SetRunning` 的持有者，真正的持有者只有「不在 Hub 页」与「模态对话框」两个。但由此暴露出一个必须处理的问题：**`IsRunning` 与「局内产线是否停 tick」不能共用一个量**。`GameManager.RunTick()` 现在只用 `IsClosedForToday` 门控 `LevelManager.TickAll()`，正是因为局内测试场景没有 HubPage、`IsRunning` 恒 false，跟着它门控会让局内产线永不推进。故落地为两个派生量：
  - `IsRunning`（时钟推进 + `VisitorManager.Tick`）= 无任何 stop reason 且未打烊
  - `IsWorldFrozen`（`LevelManager.TickAll()` 门控）= 打烊 **或** 模态对话框，**不含**页面闸门

## 9. 文本占位符与需求短语

> **2026-08-13 改写**：本节原来的「按 tag 森林组装需求短语」规则**整体作废**——访客需求重做后，

  任务卡等 UI 与台词共用同一份文本。
- 种族仍可配多条含 `{需求}` 的句式（如「我想要{需求}」「说起来……{需求}」），
