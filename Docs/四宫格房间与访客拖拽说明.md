# 四宫格房间与访客拖拽说明

> 创建：2026-08-13。Hub 场景从「一次一间、切换换图」重做为「四房间平铺的连续世界 + 自由相机」，
> 并支持把访客拖到其他房间。本文是实现沉淀：交互规格、架构落点、代码索引与已知限制。
> 架构依据：`Docs/架构设计.md` §11/§16（MVVM、表现层豁免、Prefab 约定）。

## 1. 一句话概括

四个房间平铺成 2×2 连续世界，Hub 的「当前房间」由**相机视口中心落在哪个象限**决定；
玩家滚轮缩放（缩到 0.5 倍看全四间）、左键拖拽平移，也可以**按住访客拖到别的房间**——
表现层只改坐标，松手后经 `VisitorManager.MoveVisitorToRoom` 落业务。

## 2. 交互规格

| 操作 | 行为 |
|---|---|
| 滚轮 | 以鼠标为中心缩放，0.5×（四间全览）~ 3.5×；指针须在场景区内 |
| 左键拖拽 | 平移世界；指针压在**访客/界面卡片**上时不启动平移。**家具热点不算「压住」**（2026-08-15）——它铺满房间相当一部分面积，一刀切会让在家具上按下就完全没法平移 |
| 空地双击 | 缩放 < 1×（总览态）→ 推向双击处所在的房间至满屏；缩放 ≥ 1×（房间态）→ 缩回 0.5× 总览。取代了原先的「缩小态单击选房」 |
| 单击家具 | 打开家具图鉴并**定位到被点的那一件**（带房间下标，总览态下点别房的家具也对）。**家具上只认单击、不参与双击**——否则第一击已经把面板压栈，第二击就落到面板上了 |
| 底部房间导航 / ←→ 方向键 | 相机平滑推到目标房间（0.55s InOutCubic，缩放至少 1×）；点当前房间 = 镜头复位满屏 |
| 拖动访客 | 按住业务访客拖到房间松手。**业务按状态裁决**（2026-08-13 访客需求重做）：待分房→拖进空客房即分房入住、闲逛→可换空房、前台与服务中一律拒绝；被拒时演员弹回起手位并 Toast 说明理由 |
| 访客在哪个房间 | 右侧访客卡标注（`VISITOR 01 · 卧室`）；场景里悬停访客的名牌也带 `@卧室` 前缀，拖拽跨房时实时切换 |
| 点击访客 | 前台→初次见面对话；待分房→提示拖拽分房；服务中→服务中交谈对话（验收分支在里面）；闲逛→提示。拖拽后的抬手不会误触点击 |
| 观景模式（收起界面） | 只影响四周 UI 与洗色层显隐；相机操作两种模式通用，视角不复位 |

边界规则：

- 画面**永远不露底**：任何缩放下世界都被钳在视口内（`ClampCamera`）。
- 「当前房间」跟随视口中心实时更新：导航高亮、左上说明卡（含**该房装饰分**）、家具模式的目标房间全部随之走。
  **总览态（缩放 < 1×）例外，不更新**（2026-08-15）：那时视口中心恰好落在四宫格正中心 (0.5, 0.5)，
  而 `HubWorldGrid.RoomAt` 的边界判定是 `>=`，会恒返回房间 1（卧室）。总览态本就没有「当前房间」这个概念，
  沿用缩回前的那间是最小意外；双击选房把缩放推回 1× 之后检测自然恢复。
- 每个房间的**访客活动区**与**入口区**在家具房间表可配（归一化矩形，按房间美术红框标定，2026-08-13）：
  游走落点在活动区内随机取、拖拽落点被钳在活动区内；进场从起居室入口区出现，离场走向**当前所在房间**的入口区。
- **访客在门口等待接待**：到场后就站在入口区（多人按错位站位排开），玩家接待（请进来）后才走进屋内游走；
  串门邻居同样在入口区排队等去留决定。大门在起居室（房间 0），新访客永远从起居室进场；邻居不可拖。

## 3. 架构落点（按 MVVM 分层）

```
Model / ViewModel
  VisitorInstance.RoomIndex        访客**所住房间**（默认 0 = 起居室/大堂）。2026-08-13 起是业务真相：
                                   条件类需求「房间里有没有那件家具」的判定依据，一房一客的占用校验也读它
  VisitorManager.MoveVisitorToRoom 玩家拖拽的业务入口（§8 同口径：公开方法+校验，状态不对返回 false）。
                                   按状态分派：待分房→分房+转服务中+播【开始等待服务】说出需求；
                                   闲逛→纯换房；前台/服务中→拒绝。成功后广播 InstanceChanged
  VisitorManager.IsRoomOccupied    房间占用查询（Serving 或 Wandering 都占房，离场才释放）
  FurniturePlacementQuery          房间摆放的只读查询（条件类需求的判定数据源，含初始摆放与桌面家具）

View（全部纯表现，§16.4：不回写业务、允许 deltaTime）
  HubWorldGrid                     2×2 世界坐标换算的唯一出处（房间⇄世界归一化坐标）
  HubSceneBinder                   世界搭建 + 相机：
                                     WorldClip（RectMask2D 裁剪）→ World（2× 视口大，pivot 左下）
                                       ├ RoomArt0~3（各占一个象限，贴家具烘焙图）
                                       ├ SceneWash（洗色层）
                                       ├ FurnitureHotspots（热点建在世界坐标上，跟随相机零换算）
                                       └ VisitorStage（访客舞台，覆盖全世界）
                                   相机 = World 的 anchoredPosition（平移）+ localScale（缩放）
  OutGameVisitorStage              演员持 (RoomIndex, 房内归一化坐标)，经 HubWorldGrid 换算世界锚点；
                                   拖拽 = EventTrigger 的 BeginDrag/Drag/EndDrag，屏幕→世界换算在舞台层
  OutGameVisitorActor              BeginPlayerDrag / UpdatePlayerDrag / EndPlayerDrag / TeleportToRoom；
                                   拖拽期间状态机停走、点击被吞（uGUI 的 Click 在 EndDrag 前派发，用 Dragging 标记挡住）
  HubPage                          OnVisitorDropped 把「松手」翻译成 MoveVisitorToRoom + Toast；
                                   NotifyCameraRoomChanged 同步 RoomIndex 并刷新导航
```

**拖拽的数据流**（表现先行、业务裁决）：

```
按住演员 → BeginPlayerDrag（状态机停走）
拖动     → 舞台层把屏幕坐标换算成 (房间, 房内坐标) → 演员实时跟随（纯表现）
松手     → HubPage.OnVisitorDropped → VisitorManager.MoveVisitorToRoom
             ├ 成功 → instance.RoomIndex 更新，演员留在落点
             └ 失败 → 业务不动；页面 Toast 说明理由，舞台层立刻调 actor.CancelPlayerDrag() 弹回起手位。
                      （跨房间时每帧的实例同步也会纠正，但**同房间内被拒**只能靠 CancelPlayerDrag——
                        前台访客在起居室里被拖动正是这种情况；同一条同步逻辑还负责舞台重建后的回填落位）
```

## 4. 关键实现细节

- **相机不做 uvRect 数学**：旧版单房间用 `RawImage.uvRect` 平移缩放，热点/演员逐帧换算锚点；
  四宫格改为把平移缩放放在世界根的 transform 上，热点/演员的世界锚点**建好就不用再算**，
  跟随是 uGUI 层级天然行为。
- **视口中心即当前房间**：`DetectCurrentRoom` 把视口中心反算成世界归一化坐标 → `HubWorldGrid.RoomAt`。
  相机 tween（`FocusRoom`）过程中同样逐帧检测，导航高亮在镜头推进途中就切过去。
- **平移与拖访客不打架**：场景图 `raycastTarget=false`（穿透），演员/热点吃射线；
  按下时 `EventSystem.IsPointerOverGameObject()` 为真则不启动平移——正好是「压在可交互物上」的判据。
- **平移与点家具也不打架**（2026-08-15）：家具热点**不挂 Button**（uGUI 的 Button 没有拖拽阈值，
  拖完在同一热点上松手照样触发 onClick），只挂 `HubFurnitureHotspot` 携带「哪个房间的哪件家具」；
  `IsPointerOverBlockingUI` 把最上层命中是热点的情形排除在「挡住」之外——取**最上层**而非「命中列表里有没有」，
  这样热点上面压着演员或卡片时那一下点击不会被抢走。点击与拖拽的裁决统一收到松手时的位移阈值（9px），
  平移、双击、开家具详情三处共用同一个常量。
- **滚轮与对话选项不打架**：相机输入挂在 `HubPage.HandleInput`，叠加层（对话/商店/面板）开着时
  壳不派发页面输入，滚轮天然归叠加层。
- **世界尺寸自适应**：世界根尺寸每帧校到 2× 视口（`SyncWorldSize`），分辨率变化不用重建。
- 旧的「进出卧室开关门」「交叉淡入」转场随连续相机退役（镜头推移本身就是转场）。

## 6. 已知限制与后续

- 游走/拖拽范围与门口位置已按房间配置（家具房间表「访客区/入口区」八列，Excel 导表管线）；
  但活动区是单个矩形，不能挖洞避开区内家具——需要更精细的可行走形状时再升级为多矩形/占用格。
- 前台/待分房的排队站位坐标只在起居室（仍是代码手摆 `EntrySlots`）。
- 房间语义（起居室 0 = 大堂不可分配、1~3 为客房）写死在 `VisitorManager` 的四个常量里；房间数变化要同步改常量与 `HubWorldGrid`。
- 串门邻居（ambient）不可拖、不换房。
- 热点/名牌卡随世界缩放而缩放：缩到 0.5× 时文字偏小，可接受；若要恒定大小需按 1/zoom 反缩，二轮再说。
- 房间布局（谁在哪个象限）目前定死在 `HubWorldGrid`（0 起居室左上、1 卧室右上、2 厨房左下、3 书房右下）；
  若策划要调平铺关系，只改 `CellOrigin` 一处。
