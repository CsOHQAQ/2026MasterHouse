## 1. 一句话概括

策划在 **Excel/*.xlsx** 里编辑（唯一数据源），双击 **Tools/导表/export_config.bat** 展平成
**Assets/Configs/*.csv**，Unity 资产管线感知到 CSV 变化后**自动整表重建**对应 ScriptableObject——
Unity 开着关着都不需要额外步骤。

```
Excel/*.xlsx（家具族/家具/商店/家具房间/访客三表/音效/立绘/对话）  ← 策划编辑（唯一数据源）
        │  双击 Tools/导表/export_config.bat
        │  （检查 python/openpyxl → 逐个 export_*.py）
        ▼
Assets/Configs/*.csv                                ← 自动生成，勿手改
        │  CSV 在 Assets 内：导入管线触发各 CsvPostprocessor → 对应导入器自动导表
        │  （Unity 开着：切回窗口即导；关着：下次打开时导——无需 batchmode）
        ▼
FurnitureFamilyTable / FurnitureTable / StoreTable / FurnitureRoomTable
/ VisitorRaces·ScheduleTable·TuningConfig / SfxTable / PortraitTable / DialogueTable
```

⚠ **两处顺序依赖**（都不靠 `AssetPostprocessor` 赛跑）：

| 谁必须先 | 为什么 | 怎么保证的 |
|---|---|---|
| 家具族表 → 家具表 | 家具行要按「族id」查族表，把族级属性**展开**填进自己 | 同一个 `FurnitureCsvImporter.ImportAll` 里按顺序调（§4.5） |
| 立绘表 → 对话表 | 对话导表要拿立绘表校验「立绘ID 存不存在」 | `PortraitCsvImporter` 导完立绘后**直接串调**对话导表（§7） |

bat 里也已经按这两个顺序排好。

## 2. 目录与文件

| 位置 | 内容 |
|---|---|
| `Excel/` | 各本 xlsx（编辑源）。**只放表格**，工具脚本不进这里 |
| `Assets/Configs/` | 导出的 CSV（UTF-8 BOM）。在 Assets 内是刻意设计：资产管线才能感知变化 |
| `Tools/导表/` | `export_config.bat`（总入口）、各表 `export_*.py`、`README.md` |
| Unity 侧导入器 | `Furniture/Editor/FurnitureCsvImporter.cs`（家具族/家具/商店/房间）、`Visitor/Editor/VisitorCsvImporter.cs`、`Core/Editor/SfxCsvImporter.cs`、`Dialogue/Editor/DialogueCsvImporter.cs`、`Dialogue/Editor/PortraitCsvImporter.cs`：CSV → SO 整表重建、自动导表开关、导出回写（对话表与立绘表**没有**导出回写，见 §6.7 / §6.8） |

依赖：python + openpyxl（bat 检测到缺 openpyxl 会自动 `pip install`）。

## 3. 日常使用

| 场景 | 操作 |
|---|---|
| 改数值/加行 | 改 xlsx → 双击 bat → 切回 Unity（自动导表，Console 打 `[导表] 完成`） |
| Unity 开着想立即导 | 菜单 `MasterHouse → 家具系统 → 从 CSV 导入家具四表`（或配置中心里的按钮） |
| 关掉自动导表 | 菜单 `MasterHouse → 家具系统 → 自动导表（CSV 变化时）`（勾选开关） |
| 从资产反向生成 CSV | 菜单 `MasterHouse → 家具系统 → 导出家具四表到 CSV`。**只回写 CSV，不回写 xlsx** |
| 配置中心入口 | `MasterHouse → 配置中心`（Ctrl+Shift+M）里有导入/导出/打开 Excel 目录按钮 |

**心智模型：导入是整表重建，以表格为准。** Inspector 里对这两张 SO 的手改会在下次导表时被覆盖——
要么改表格，要么别导表，一个字段只能有一个家。

## 4. 表格规范（xlsx 通用约定）

- **第 1 行 = 中文列名**（导出/导入按列名索引，列顺序可在 Excel 里随意调整，但列名文字不能改）。
- **第 2 行 = Unity 字段名**（灰色斜体，如 `id` / `displayName` / `tableSurface.enabled`）——纯参考行，
  导出脚本检测到"全 ASCII 标识符"会自动跳过。
- **行序即资产内条目顺序**（收纳栏、商店列表的展示顺序）。
- **多选值用 `/` 分隔**（也兼容 `、` `,`），如表面类型 `地面/桌面`。
- **布尔列填 `是`/`否`**（兼容 1/true）。
- **图片列两种写法**：
  - Resources 相对路径（不带扩展名）：`OutGameUI/Furniture/table`
  - Assets 完整路径（带扩展名）：`Assets/PC ui/Scene/furniture/002_red_armchair 1.png`
  - SO 存的是 Sprite 引用，运行时不经路径加载，素材**不必**位于 Resources。
- 空行自动跳过；缺 id 的行跳过并打 Warning。

## 4.5 家具族表.xlsx（工作表「家具族」→ FurnitureFamilyTable）

**2026-08-15 新增。** 同款家具的换色变体（台灯·01~06）归为**一个族**，族级共有属性只在这里填一次。

| 列 | 字段 | 说明 |
|---|---|---|
| 族id | familyId | 稳定键，家具表的「族id」列引用它。现有 15 族沿用 id 前缀（`single_sofa`、`table_lamp`…） |
| 族显示名 | displayName | 商城卡片标题、收纳栏槽位名，如「单人沙发」；变体名仍是「单人沙发·02」，**不自动拼接** |
| 分类 | category | 商店页签：`盆栽`/`摆件`/`桌椅`/`壁挂`/`灯具`（空值按摆件） |
| 描述 | description | 商店详情与获得弹窗文案（空则显示占位句） |
| 表面类型 | surfaces | **可多选**：`地面`/`桌面`/`壁挂`，`/` 分隔；决定能吸附哪类网格、出现在哪些收纳页签 |
| 可叠放 | stackable | `是` = 地毯类：不挡其他家具落格、渲染压底；地毯彼此仍互斥 |
| 占格列/占格行 | cols/rows | 占用网格尺寸 |
| 装饰分 | decorationScore | 摆放后对该房间装饰分的贡献。**这个数会变成钱**（2026-08-15）：客人**完成服务**离场时，小费 = 基础小费 + 该房装饰分 ÷ `EconomyConfig.decorScorePerTip`。被拒绝/超时的客人只拿基础小费 |
| 拿起/放下音效 | pickupSound/putdownSound | 写法同图片列（Resources 或 Assets/ 路径）；空 = 全局默认音 |
| 桌面格启用 + 5 参数 | tableSurface.* | 仅带桌面的家具（茶几等）填；列数/格宽/格高/偏移X/桌面高度。⚠ **全表至少要有一族启用**，否则那些「桌面」表面的家具在场上无处可放（现由 `round_table` 承担：启用 + 偏移X 4，3 列 × 64 = 192 居中于圆桌 200 显示宽） |

**心智模型：改一处、整族生效。** 想把「单人沙发占几格」从 3 列改成 4 列，改族表这一行，
11 个配色变体全部跟着变——不用去家具表改 11 行，也就不会漏改一行留个隐性 bug。

**导入时会展开。** 上面这些列在导入时被**逐行填进** `FurnitureTable` 的每一个变体，
所以 SO 里看到的每行家具字段依然是齐全的（商城/摆放/装饰分/需求匹配等消费方一行都没改）。
这份冗余是机器生成的产物——**别去 Inspector 里改展开后的值，下次导表就被覆盖**。

校验规则：

| 级别 | 规则 |
|---|---|
| 报错 | 族 id 为空；族 id 重复；族显示名为空；**家具行引用了不存在的族**（指名 CSV 行号与对应 Excel 行号，该行跳过） |
| 警告 | 族在家具表里没有任何成员（刚建还没配家具是正常的，不阻塞） |

> 「家具行引用了不存在的族」刻意报**错**而不是用默认值兜底：兜底会得到一件占格 1×1 的沙发，
> 要摆进房间才发现，极难查。

## 5. 家具表.xlsx（工作表「家具」→ FurnitureTable）

**2026-08-15 族化后这张表只剩逐变体不同的列**（22 列 → 8 列），族级列全部搬去了 §4.5：

| 列 | 字段 | 说明 |
|---|---|---|
| id | id | 唯一稳定键，摆放/存档/商店引用它 |
| 英文索引 | nameKey | 素材文件名里的英文名，检索/对照用，不上屏（2026-08-13 新增） |
| 显示名 | displayName | 界面显示（中文），带变体编号如「单人沙发·02」 |
| 族id | familyId | 所属族，填 §4.5 的族 id。**必填**，填错会报错跳过该行 |
| 显示宽/显示高 | displayWidth/Height | 场景像素。**逐变体微调**（按素材实测），所以留在本表而不是族表 |
| 精灵图 | sprite | 见 §4 图片列 |
| 色值 | swatchColor | `#RRGGBB`，商店与收纳栏选色块的颜色；按素材平均色生成，策划可改 |

价格与解禁声望在**商店表**（§5.5，2026-08-13）；分类/表面/占格/装饰分/音效/桌面格在**家具族表**（§4.5）。

> **为什么显示宽也留在变体行**：实测 121 行里有 9 个族的显示宽、4 个族的显示高逐变体不同，
> 它与显示高本就是一对。**不引入「族默认值 + 变体覆写」**——那会让同一个数值有两个家。

## 5.5 商店表.xlsx（工作表「商店」→ StoreTable）

家具的售卖配置**独立成表也独立成资产**（`Assets/Resources/OutGameUI/StoreTable.asset`），按 id 关联家具表：

| 列 | 字段 | 说明 |
|---|---|---|
| id | furnitureId | 对应家具表的 id（引用不存在的家具会告警跳过） |
| 显示名 | - | 仅供对照阅读，导入忽略（以家具表为准） |
| 价格 | price | 购买价。**必须 > 0**（2026-08-15）：家具改为不限数量重复购买后，0 价 = 免费无限领，而装饰分直接加成小费，等于开放零成本刷钱。`TryPurchaseFurniture` 会把 ≤ 0 的挡成 `NotForSale`。回收价 = 价格 × `EconomyConfig.sellbackPercent`（默认 50%） |
| 解禁声望 | unlockReputation | 未达到时商店/收纳呈「？」。这是**声望唯一的作用**，别全配 0——全 0 等于声望不存在。现行分档 0 / 70 / 140 / 230：家具本体开局可买，灯具与摆件靠声望解锁 |

⚠ **配解禁声望的硬约束**：条件类需求点名的家具必须落在玩家**当天够得到**的档位。现行日程第 1 天第 2、3 位客人就要 `single_sofa_06` 与 `round_table_06/08`，所以这三件（及其所属族）必须留在 0 档，否则开局需求直接做不到。改档位前先看一眼 `Assets/GameData/Needs/` 里各 `ConditionNeedDef` 点了什么。

**不在商店表里的家具 = 非卖品**，等价于价格 0 / 解禁 0——它买不到（`NotForSale`），也不再自动算作初始拥有。**开局拥有什么由 `HouseEconomyConfig` 决定**：全部房间的初始摆放数（代码自动统计，保证「拥有 ≥ 已摆」）+「初始携带家具」列表里配的份数。

另有工作表「分类」（→ `商店分类表.csv` → `StoreTable.categories`）：分类名 + 一行描述，商店 TAB 头与右侧信息区的文案（2026-08-14 设计稿 §1）。

商店展示按**家具族**聚合（家具表的「族id」列，见 §4.5）：一族一张卡，右侧色块行选配色（悬停即预览、X 键循环），买哪个颜色背包里就是哪件。
2026-08-15 前这里是按 id 前缀猜族的，族表落地后已改读显式字段；盆栽「平铺不聚合」的特例也随之删除——只有一个成员的族自然就是一张单卡。

代码侧读取一律经 `EconomyManager.PriceOf(entry)` / `UnlockReputationOf(entry)`，表现层不直接摸表（§11.4）。

## 6. 家具房间表.xlsx（四张工作表 → FurnitureRoomTable）

明细行通过「房间id」挂到房间；坐标与尺寸全部为场景图像素（原点左上、Y 向下，场景逻辑尺寸 1672×941）。

| 工作表 | 列 | 说明 |
|---|---|---|
| 房间 | 房间id、显示名、场景宽/高、背景图、景深模糊图、失焦模糊图、初始货币、**访客区左/下/右/上、入口区左/下/右/上**（归一化 0~1，左下原点，按房间美术红框标定） | 行序 = Hub 房间下标（0~3 对应起居室/卧室/厨房/书房）；访客区=游走/拖拽范围、入口区=进离场门口（四宫格说明 §2） |
| 网格 | 房间id、网格id、表面类型、列数、行数、格宽、格高、X、Y | 当前为全图开放：壁挂 27×9@(26,20)、地面 27×8@(26,581) |
| 占用格 | 房间id、网格id、列、行 | 背景画面里禁止摆放的格子（新空房间图无占用格） |
| 初始摆放 | 房间id、家具id、网格id、宿主家具id、列、行、翻转 | 地面/壁挂填网格id；桌面家具填宿主家具id（二选一）；翻转=左右镜像 |

> **「宿主家具id」在导表期会被翻译成坐标**（2026-08-15，家具库存说明 §5.4）。资产里存的是宿主的落位
> `hostGridId/hostCol/hostRow`，因为家具可重复购买后同房间能摆多件同款，家具 id 不再唯一标识一件实例——
> 按 id 找宿主会把两张桌子上的东西全解析到第一张，挤不下的还会被静默丢弃。
> 你在 Excel 里照旧填家具 id，翻译由导入器做；**同房间摆了多个同 id 候选时会 LogError 并丢弃该行**，
> 想在两张同款桌上放不同东西就把其中一张换个配色。

注意：**默认摆放只在该房间从未动过家具时生效**；正在 Play 需重进或 GM 重置才能看到新默认。

## 6.5 访客三表（2026-08-12 新增）

三张 xlsx → 四份 CSV → `VisitorCsvImporter` 自动重建访客侧全部配置资产：

| Excel | 工作表 | CSV | 目标资产 |
|---|---|---|---|
| 访客种族表.xlsx | 种族 | 访客种族表.csv | `VisitorRaces/Race_<raceId>.asset`（缺则新建；CSV 里没有的旧资产保留并告警） |
| 访客日程表.xlsx | 日程 | 访客日程表.csv | `VisitorScheduleTable.asset`（整表重建） |
| 访客调参表.xlsx | 调参 | 访客调参表.csv | `VisitorTuningConfig.asset`（键值对：openMinute 等 7 项） |
| 访客调参表.xlsx | 氛围访客 | 访客氛围表.csv | 同上 `ambientVisitors` 列表 |

> **2026-08-14 对话资源重构的两处改动**：种族表删掉「对话池」列（对话内容改由对话表按 `raceId` 关联，见 §6.7）；
> 调参表新增 `needPromptMinTicks` / `needPromptMaxTicks` 两行——访客入住后先安顿这么久才开口说需求，
> **服务超时也从他开口那一刻才起算**。
>
> **2026-08-14 立绘 ID 化的两处改动**：
> ① 「立绘差分」列 → **「默认立绘ID」列**，填 `Excel/立绘表.xlsx` 里的立绘ID（如 `fox_平静`）。
> 原来那种 `平静=路径/高兴=路径` 的双层分隔串是 §16.6 明令禁止的无类型数据，差分整体搬去立绘表（§6.8）。
> 这一列用在两处：Hub 访客栏小卡；对话组首句没填立绘ID 时的起点。留空 = 该种族不显示立绘。
> ② **「跨天留宿概率%」列删除**——它的消费方（闲逛访客的跨天 roll）在更早的一次改动里就移除了，
> 当时留字段等清理，这就是那一轮。日结面板的「跨天留宿 N 位」是实际人数统计，与本列无关，仍然照常显示。

引用列写法（解析失败打 Warning 不中断）：

- **默认立绘ID**：写 `Excel/立绘表.xlsx` 的主键，如 `fox_平静`。**ID 的存在性由立绘表那边负责**——
  访客导表不查表（导表顺序不保证，在这里查会报出「立绘表还没导」的假错误）。写错的后果是这位访客没有脸。
- **具名覆写**：写资产名；空 = 不引用。
- **日程表的需求**（2026-08-13 新增列，**必填**）：写 `NeedDef` 的**资产名**（如 `Need_落地灯`）。
  需求资产在菜单 `MasterHouse → 访客系统 → 需求编辑器` 里建（左树分「条件类 / 小游戏类」，家具 id 走下拉）。
  **留空的行运行时会 LogError 并跳过投放**——新模型下没有需求的访客无事可做。
  已知代价：改资产名即断引用，且 Unity 的「查找引用」查不到 Excel 里的字符串，这是 Excel 引用 SO 的固有问题。
- **日程表的种族id**：写 raceId 或显示名均可。
- **日程表的出现时刻**语义是「**最早**出现时刻」：前台满员（含待分房，上限 2 人）或三间客房住满时投放会卡住等待，
  玩家腾出位置后下一位立刻进场（访客需求重做说明 §5.4）。当天打烊仍未投放的行**作废并打 Warning**，不顺延次日。

> **种族表的「需求权重 / 需求数下限 / 需求数上限」三列已于 2026-08-13 删除**：需求体系由 tag 权重 roll
> 改为「日程条目逐条配死一条 `NeedDef`」（访客需求重做说明 §4.2/§9.1），种族不再参与需求生成。

种族表当前的完整列：`种族id / 显示名 / 等搭话超时tick / 等交货超时tick / 闲逛上限tick / 默认立绘ID / 序列帧`。

⚠ 别把**默认立绘ID**和**序列帧**搞混：前者是对话页面与访客小卡上的那张大立绘（`Portraits/*.png`），
后者是场景里走来走去的小人（`Visitors/*_await_sheet.png`）。两套素材、两条链路，互不相干。

⚠ 序列帧那一列**也接受单张定格图**：`*_await_sheet.png` 旁边没有同名 json 时按 1×1 单帧处理
（2026-08-16 入库的 QQ 小人就是这样，一个姿势一张图）。`*_attack_sheet` 是「服务完成庆祝」那一下，
没有就不播、直接转闲逛，不报错。

⚠️ 日程条目下标仍是派生种子的一部分（§6.1）：需求已改为配死、不受影响，但**重排/插入既有日程行会改变对话抽取结果**，加内容请追加在表尾。

## 6.7 对话表（2026-08-14 重构，本文最复杂的一张）

`Excel/对话表.xlsx`（三个工作表：**对话组** / **对话内容** / 参考）
→ `Assets/Configs/对话组表.csv` + `对话内容表.csv`
→ `DialogueCsvImporter` **整表重建** `Assets/Resources/OutGameUI/DialogueTable.asset`。

**与其它表的两处不同，先记住：**

1. **没有导出回写**。其它表可以从 SO 反向生成 CSV，对话表不行——SO 是产物不是源，
   回写会造出第二个家。要看现有内容就打开 xlsx。
2. **有错误就整体不落盘**。其它表是逐行跳过坏行继续导，对话表一旦有错就
   **一个字都不改** `DialogueTable.asset`——半张对话表比没有对话表更难查。
   错误全在 Console，每条都带 `对话表.xlsx[对话内容] 第 37 行：……`。

原来那套「一个对话组一个 SO + 一个种族一个对话池 SO + 对话编辑器窗口」已整体退役：
Excel 成为唯一源之后，散资产的三条理由（diff 友好、多人并行、拖拽引用）全部失效，
留着只会制造孤儿资产。

### 6.7.1 第一页「对话组」：把组挂到池上

| 列 | 说明 |
|---|---|
| 对话组ID | int，对应第二页。建议分段：`1xxxx` 初次见面 / `2xxxx` 等待接待 / `3xxxx` 需求对话 / `4xxxx` 需求反馈 / `5xxxx` 闲聊 / `6xxxx` 告别（只是约定，不强制） |
| 种族 | **一个 `raceId`，仅此一个**。「通用」与 `/` 多选已于 2026-08-14 作废，见下方 ⚠ |
| 需求ID | `NeedDef` 的**资产名**（如 `Need_修理电路`）。见下表的填写规则 |
| 所属对话池 | 九个英文 key 之一，有下拉 |
| 进入条件 | 函数调用串，`;` 分隔多条、隐式 AND；留空 = 无条件参与抽取 |
| 备注 | 仅供阅读，导入忽略 |

⚠ **一个对话组只属于一个种族（2026-08-14 立绘 ID 化的硬前提）**

原先「种族」列支持 `通用` 与 `fox/crow` 多选，导入期展开成多条池挂载——但它们指向的是
**同一个对话组、同一份台词行**。这在表情还是枚举时没问题：枚举是种族无关的键，
每个访客拿着自己的差分表去查，各顶各的脸。立绘改成具体 ID（`fox_高兴`）之后，
共用台词就等于共用立绘——一组通用台词会让鸦族兔族猬族全都顶着狐狸的脸。

于是规则收紧成一组一种族，导表期两道一起堵：

- 单行写「通用」或 `fox/crow` → 报错（`ResolveRace`）
- 同一个组ID 分散在多行、挂给不同种族 → 报错（`CrossValidate`）
- 同一个组ID 挂进**多个分类**仍然允许，只要那些行的种族一致

代价是内容量随种族数线性增长（原来一组通用的，现在要按种族各抄一份）。
这是**明知代价后的选择**：每个种族本来就该有自己的性格与长相。

九个分类：

| key | 中文 | 时机 |
|---|---|---|
| `firstMeeting` | 初次见面 | 首次点击前台**队首**访客。组内要有「接待 / 拒绝」分支 |
| `waitingReception` | 等待接待 | 同一位前台访客的二次点击。**同样要带接待/拒绝分支**，否则玩家 ESC 之后再也接待不了他 |
| `needTalk` | 需求对话 | 入住并示意后点击他。说需求 + 交付/推迟/放弃分支。**需求ID 必填** |
| `feedbackDisappointed` | 需求反馈·失望 | 服务超时，需求没办到 |
| `feedbackPlain` | 需求反馈·一般 | 小游戏低分。**条件类走不到这一档**，别给条件类在这里写台词 |
| `feedbackFine` | 需求反馈·还行 | 小游戏中间分。同上 |
| `feedbackPerfect` | 需求反馈·完美 | 条件类交付成功 / 小游戏满分 |
| `smallTalk` | 闲聊 | 停留期冒泡，走场景气泡。**一组只显示第一句**，要多句就拆成多组 |
| `farewell` | 告别 | 停留到点后转「待告别」，**玩家点他才播**。组里**必须有一行 `Action | Leave`**，见下方 ⚠ |

⚠ **【告别】是全表唯一「由内容决定访客什么时候走」的分类**

其余八类的业务推进都由访客状态机自己走完，对话只是旁白。告别反过来：客人停留到点后
**不再自动离开**，而是站在自己房间里等玩家点他（头顶亮「！」）；播到那条 `Leave` 事件他才真的走。

- **`Leave` 必须是所在路径的最后一个事件**——它一执行访客就离场、演员开始走向门口，
  后面还有台词会读成「人都走了还在说话」。校验器给警告
- **不配 `Leave` = 客人永远不走**，一直占着那间客房。校验器给警告，但不是错误——
  玩家随时能再点他重播一次，不是死局
- 玩家播到一半按 ESC 也一样：`Leave` 没执行，他继续等着，再点一次即可
- **告别按「纯台词 + 末尾一条 Leave」配就够了**，不需要分支

**需求ID 的三条规则**：

- `needTalk` **必填**——一条需求配自己的一套说辞。工程里任何一条 `NeedDef` 缺了它，
  校验器报错（那位访客点开不会有任何反应，只能等超时）
- 四档反馈与 `farewell` **选填**——填了就是这条需求专属，抽取时**专属优先**；
  没有专属才回落到留空的通用组（「谢谢你修好我的电路」这种告别词就该按需求写）
- 其余三类**必须留空**——需求还没透露（前两类）或已经办完了（闲聊），填了会报错

### 6.7.2 第二页「对话内容」：组里的每一步

| 列 | 说明 |
|---|---|
| 对话组ID | 每组首行写一次，**后续行留空 = 沿用上一行**（导出时自动补全） |
| 说话人 | `visitor` / `player` / `narration`，有下拉。Action 行留空 |
| 立绘ID | `Excel/立绘表.xlsx` 的主键，有下拉。**只对访客句生效**。**留空 = 沿用上一句**（GVN 惯例，只在需要换脸时才填）；组内首句留空则用该种族的「默认立绘ID」。填了的 ID 必须存在于立绘表，否则导表报错 |
| 步骤 | 主线序号，从 1 起 |
| 选项 | 分支选项号，从 1 起。**主线行留空** |
| 句序 | 选项后面第几句，从 1 起。**选项行本身留空** |
| 类型 | `Line`（说一句话）/ `Action`（执行事件）/ `Branch`（一个选项） |
| 文本 | Line = 台词；Branch = 选项文字；**Action = 事件调用串** |
| 条件 | 只对 Branch 行有意义 = 该选项的可选条件；`;` 分隔多条 |

**三列数字序号是刻意的**（不是 `3-1` 那种复合写法）：`3-1` 在中文 Excel 里输入即被识别成日期；
更要紧的是三列之后**行序完全没有语义**——可以任意排序、插行，解析结果一模一样。

一个完整的分支长这样：

```
组ID   说话人   立绘ID      步骤 选项 句序 类型    文本                      条件
10001  visitor  fox_平静     1              Line    你好，请问今晚还有空房吗？
                             2    1         Branch  有的，请进                CanAcceptGuest
                             2    1    1    Action  Accept
       visitor  fox_高兴     2    1    2    Line    太好了，谢谢你！
                             2    2         Branch  抱歉，今天恐怕招待不了你
                             2    2    1    Action  Reject
       visitor  fox_失望     2    2    2    Line    这样啊……那我改天再来。
```

「立绘ID 留空 = 沿用上一句」让连着几句同一个表情时不必重复填：

```
1  visitor  fox_困惑   我遇到点麻烦……
2  visitor  (留空)     你能帮帮我吗?      ← 仍是困惑脸
3  visitor  fox_高兴   太好了!            ← 到这一句才换
```

承接发生在**播放期**（`DialogueManager.CurrentPortraitId`），不是导表期——
分支之后汇合回主线时该顶哪张脸取决于玩家选了哪个选项，静态展不开。这也正是 GVN 的语义。

规则：

- **每个分支至少要有一个不填条件的选项**——条件全不满足时对话会卡死，玩家只能 ESC。硬校验
- **选项子句播完 → 汇合到主线的下一步**。分支放在组尾时「汇合」天然等于「结束」
- **不支持嵌套分支**（子句里再出 Branch），一层就够
- **没有跨组跳转**：分类拆细之后接待/拒绝/交付全在组内解决
- 占位符：`{需求}`（取 `NeedDef.description`）、`{访客名}`。未知占位符原样显示

### 6.7.3 条件与事件：写函数名

「进入条件」「条件」「Action 行的文本」三处填的都是函数调用串：

```
HasEmptyRoom                       无参
DayAtLeast(3)                      带参
CompleteNeed(perfect)              带参
DayAtLeast(3);ReputationAtLeast(10)   两条，隐式 AND
Log("含,逗号的文本")                 双引号保护
```

可用函数见 xlsx 的**「参考」页**，代码侧的唯一真相源是
`Assets/Scripts/Dialogue/DialogueFuncs.cs` 里的两张字典。**加一条判定 = 加一行代码**——
这是刻意的取舍：判定逻辑本来就是代码，换来的是**零反射**（没有 IL2CPP 裁剪风险、
没有启动扫描），以及「函数名与参数个数写错，导表时当场报出 Excel 行号」。

常用的几条：

| 条件 | 含义 |
|---|---|
| `CanAcceptGuest` | 现在能接待新客人（有空房 且 没有别人在等分房）。挂在「接待」选项上 |
| `RoomHasNeedFurniture` | 所住房间里摆着他要的家具之一。**条件类需求的验收判据** |
| `DayAtLeast(N)` / `CurrencyAtLeast(N)` / `ReputationAtLeast(N)` | 阶段性内容门槛 |

| 事件 | 含义 |
|---|---|
| `Accept` / `Reject` | 接待（转待分房）/ 拒绝（扣声望并离场） |
| `CompleteNeed(档)` | 完成需求结算，留空 = `perfect`。**奖励类** |
| `StartMinigame` | 小游戏类需求的开局口 |
| `AddCurrency(N)` / `AddReputation(N)` | **奖励类** |
| `Leave` | 送别离场。**只在【告别】组里有效**，别的分类填了不会生效（只打一条 Warning） |

⚠ **奖励类事件必须是所在路径的最后一个事件**（主线末尾或某个选项子句的末尾）。
放中途的话，玩家播到那里按 ESC 再点开可以反复领取——校验器会给警告。
`Leave` 同样只能放末尾，理由不同：见 §6.7.1 关于【告别】的那段 ⚠。

### 6.7.4 菜单与故障排查

| 场景 | 操作 |
|---|---|
| 改台词 | 改 xlsx → 双击 bat → 切回 Unity（自动导表） |
| Unity 开着想立即导 | 菜单 `MasterHouse → 对话系统 → 从 CSV 导入对话` |
| 关掉自动导表 | 菜单 `MasterHouse → 对话系统 → 自动导表（CSV 变化时）` |
| 随时全量校验 | 菜单 `MasterHouse → 对话系统 → 校验对话表` |
| 重建一张空模板 | `python Tools/导表/make_dialogue_template.py --force`（**会丢掉现有台词**） |

| 现象 | 原因与处理 |
|---|---|
| bat 里对话那步报一串 `[对话内容] row N` | 格式层错误（ID 不是数字、类型写错、步骤号重复），照行号改 |
| Console 报「未知的条件/事件函数」 | 函数名拼错，或者代码里还没有这一条——对照「参考」页与 `DialogueFuncs.cs` |
| Console 报「需求 X 没有给种族 Y 配 needTalk」 | 新加了需求却忘了写台词，在第一页补一行 |
| 「分支没有无条件选项」 | 那一步的所有选项都填了条件，至少留一个空的兜底 |
| 「「立绘ID」在立绘表里找不到」 | 拼错，或者立绘表里还没这一行——先去 `Excel/立绘表.xlsx` 加行（§6.8） |
| 「种族不再支持「通用」/ 多选」 | 一组一种族（§6.7.1 的 ⚠），把这一组按种族复制成多组 |
| 「对话组 N 被挂给了两个种族」 | 同一个组ID 出现在多行且种族不同，同上 |
| 点访客没有任何反应 | 先看他卡上的状态：排队中 / 正在安顿 都是**没有对话**的正常状态，不是 bug |
| 客人道完别还赖着不走 | 那一组【告别】里没有 `Action \| Leave`，在组末尾补一行 |
| 客人到点没等玩家道别就走了 | 那个种族**一组 farewell 都没有**——运行时不会把他永久卡在场上，会打一条 Warning 直接放行 |

## 6.8 立绘表（2026-08-14 新增）

`Excel/立绘表.xlsx`（工作表「立绘」）→ `Assets/Configs/立绘表.csv`
→ `PortraitCsvImporter` **整表重建** `Assets/Resources/OutGameUI/PortraitTable.asset`。

全表只有三列，刻意保持朴素：

| 列 | 说明 |
|---|---|
| 立绘ID | **主键**。对话表第二页的「立绘ID」列、访客种族表的「默认立绘ID」列引用它。唯一硬约束是不能带逗号（CSV 分隔符）；除此之外命名完全自由 |
| 资源路径 | **Resources 相对路径、不带扩展名**，如 `OutGameUI/Portraits/rabbit`。立绘走 `Resources.Load<Texture2D>` 取图，所以素材必须待在某个 `Resources` 目录下（美术交付件在 `Assets/Arts/对话大头`，那儿不是 Resources，得先拷进来——见 `Tools/install_visitor_art.py`） |
| 备注 | 仅供阅读，导入原样存下不参与玩法 |

### 为什么是 ID 而不是枚举

原先立绘住在 `VisitorRaceDef.portraits` 上，索引键是硬编码的五项表情枚举
（`calm/happy/confused/sad/surprised`），配置写成一列 `平静=路径/高兴=路径` 的双层分隔串。

枚举的前提是**差分能归类**。美术要求「更多差分、且不太好归类」之后这个前提就没了——
硬塞进五个格子只会让策划在「这张算 happy 还是 surprised」上做无意义的选择题，
而加一个差分要改代码、改枚举、动已配的资产。所以退回最朴素的形式：**加一张图 = 加一行**。

代价是失去了「一组台词多种族共用」（枚举是种族无关的键，ID 不是），
连带把对话表的「通用」种族一起作废了——见 §6.7.1 的 ⚠。

### 校验口径

| 检查 | 在哪 | 严重度 |
|---|---|---|
| ID 空 / 重复 / 带逗号、路径空 | `export_portrait.py`（bat 阶段） | 错误，CSV 不落盘 |
| 同上（再查一遍） | `PortraitCsvImporter` | 错误，**整表不落盘** |
| 路径指向的贴图不存在 | `PortraitCsvImporter` | **警告**——美术流程里「先占 ID 后补图」是常态，拦下来会连累整张对话表 |
| 对话表引用的立绘ID 存不存在 | `export_dialogue.py` + `DialogueCsvImporter` | 错误，对话表整表不落盘 |

| Unity 开着想立即导 | 菜单 `MasterHouse → 对话系统 → 从 CSV 导入立绘` |

  `VisitorCsvImporter.CsvPostprocessor` 监听 `访客种族表/日程表/调参表/氛围表.csv`，
  `SfxCsvImporter.CsvPostprocessor` 监听 `音效表.csv`，
  `DialogueCsvImporter.CsvPostprocessor` 监听 `对话组表.csv`、`对话内容表.csv`，
  `PortraitCsvImporter.CsvPostprocessor` 监听 `立绘表.csv`
  的导入事件 → `EditorApplication.delayCall` 里执行导表。自动导表开关四套（家具 / 访客 / 音效 / 对话），
  **立绘与对话共用「对话系统」那一个**。
- **族表 → 家具表的展开（2026-08-15）**：家具行的族级属性来自族表，所以族表必须先解析。
  这里**不需要串调**——两张表共用一个 `FurnitureCsvImporter.ImportAll`，顺序写死在方法体里
  （族 → 家具 → 商店 → 房间），无论 postprocessor 收到哪张 CSV 的变化都是整批重导。
- **立绘 → 对话的串调（2026-08-14）**：对话导表要拿立绘表校验立绘ID，两个 postprocessor
  谁先跑并不保证。若先跑对话，会报出一屏「立绘ID 不存在」的假错误（新立绘还没导进来）。
  所以：`PortraitCsvImporter` 导完立绘后**直接调用**对话导表；对应地
  `DialogueCsvImporter` 的 postprocessor 发现同一批导入里也有 `立绘表.csv` 时**让路**返回。
  立绘导表报错时不会往下串——拿旧表去校验对话只会误导。
- **Sprite 自愈**：表里引用的 `Assets/` 素材若没按 Sprite 类型导入（3D 模板默认 Default），
  导入器自动改 TextureImporter 为 Sprite/Single 并重导后重取引用。
- **防回环**：菜单「导出到 CSV」写文件前置 `suppressNextAutoImport`，跳过随之而来的一次自动回导。
- **合法性**：房间行必须排在其明细行之前（导出脚本已保证顺序）；引用不存在房间/丢失精灵会打 Warning 但不中断。

## 8. 新增一类配置表的步骤

以「新表 X」为例（照抄家具表的模式）：

1. `Excel/X表.xlsx`：第 1 行中文列名 + 第 2 行英文字段名。
2. 复制 `Tools/导表/export_furniture.py` 为 `export_x.py`：改 `EXCEL_PATH`/`OUTPUT_PATH`/`HEADER`/`SHEET`。
3. `export_config.bat` 加一步：`python "%~dp0export_x.py"` + errorlevel 检查。
4. Unity 侧在 `FurnitureCsvImporter`（或新建 `XCsvImporter`）加：CSV 路径常量、表头数组、
   Import 方法（`LoadOrCreate<XTable>` + 逐行解析）、`CsvPostprocessor` 监听路径。
5. 若表里有图片引用，直接复用 `LoadSprite`（两种路径写法 + 自愈都是现成的）。
6. 若新表要被别的表按 id 引用（像家具族表那样），把它的 Import 排在引用方**之前**、写在同一个
   `ImportAll` 里；引用不到时报错并指名行号（`Where(row)` 会把 CSV 行号换算成 Excel 行号），不要静默兜底。

家具族表（§4.5）就是照这五步加的，可以直接当范例对照。

## 9. 故障排查

| 现象 | 原因与处理 |
|---|---|
| bat 报 `PermissionError` / 写入失败 | xlsx 正被 Excel 打开锁住——关掉再跑 |
| bat 提示需要 python | 装 python 并加入 PATH；openpyxl 缺失时 bat 会自动 pip install |
| bat 出现乱码/命令不识别 | bat 必须保持**纯 ASCII**（当前提示语为英文即为此），别往里加中文 |
| 切回 Unity 没触发导表 | 检查菜单「自动导表（CSV 变化时）」是否被关；或手动菜单导入 |
| Console 报「精灵图未找到」 | 路径写错（对照 §4 两种写法），或素材未导入——该行 sprite 置空不中断 |
| 表里改的没生效 | 确认跑过 bat（CSV 时间戳变了）且 Unity 已聚焦；Inspector 手改会被导表覆盖属正常 |
| 加了新列但资产里没有 | 新列的 **CSV 与导入器代码同批变更**时，Unity 会先用旧代码导表、随后的域重载又吞掉自动导表——手动菜单「从 CSV 导入」一次即可（或改一下 CSV 内容再聚焦） |
| 家具在场景里比例不对 | 改「显示宽/高」；素材源图与场景的换算基准见家具表初值说明（×0.18 起步目测校准） |
